# 固定FA的精简编辑迁移小试

仅在Linux运行的隔离诊断，固定3个有原证书的编辑、4个共同其他成熟父代和每臂12次查询；5臂总计60FE，另4次导入QA。

- `transfer_common.py`：冻结路径、只追加IO、基因编码与既有评价器的TSV适配。
- `transfer_edits.py`：源编辑移植、同实际字段规模的普通控制、厂内排序位移记录。
- `freeze_transfer.py`：旧冻结身份验证、源内实际编辑掩码、FA资格、接收者和全部提议冻结；保留0FE修订证据。
- `verify_transfer.py`：独立字段约束、真实规模匹配、实际类与完整时间轴核验，无额外解码。
- `run_transfer.py`：沿用已验收Java classpath，先4QA，再60FE，失败停止且不补预算。
- `transfer_metrics.py`、`analyze_transfer.py`：固定共同参考集、逐父代配对、三指标和预登记取舍。

完整对照只复制源父子实际不同的字段。普通控制匹配工件、字段类型与实际替换字段数，不保证相同排序位移；分别报告三个随机流，不择优合并。

冻结Java入口的`mask`列只作为本轮记录标签，QA为0，PAID为1；真正源编辑位由`queries.json`的`sourceAtomMask`记录，臂由`arm`和唯一`id`区分。Java不根据该标签生成候选，全部四向量由已冻结输入给定。它仍通过共同RunContext和完整解码器计费。

有效运行：`runs/linux-edit-transfer-20261106-02`。`-01`是评价前0FE修订，未删除。原目录禁止覆盖或自动重跑；复现实验需要新的明确预算和目录。

结论与边界见`docs/精简编辑迁移小试结果-2026-11-06.md`。不改变四职责、原共享或默认主线。
