# NSGA-II差距原因审计：先复核基线语义，再解释搜索效率

日期：2026-11-02。范围：只审计论文、已运行的冻结源码、270次原始记录及付费前沿；未调参、未修改搜索代码、未启动优化器或重算调度。新增FE为0。

**当前结论是两层问题叠加：存在必须优先处理的基线重建非等价；现有配置的单位评价搜索质量也确实落后。未发现输入、预算或HV计算偏袒NSGA-II。** 各因素解释了多少差距，尚无因果消融证据，不能分配归因比例，也不能保证补齐基线后就能反超。

## 1. 三类问题分别判断

|问题|已确认的事实|本轮能下的结论|
|---|---|---|
|基线实现/论文语义|第四章代末100选100；正文要求局搜前后合并，而当前未合并；更新算子的片段与随机关联也不等价|必须先补充语义验收，当前A0-v2不能代表已完整落实论文搜索语义|
|比较公平性|270次输入、预算、计费入口一致；810个HV独立重算吻合；共同外部档案接收全部成功评价候选|没有发现足以推翻这轮配置比较的计费或指标错误；仍只是开发期短预算适配比较|
|搜索机制效率|同FE仍落后；大实例SHARE评价更多却更差；部分前沿被NSGA-II全部支配|有单位评价质量不足的证据，不能只怪解码速度或模块成本；具体生成/保留责任未分开|

前次工程验收主要证明合法性、预算、目标重放和复现，没有充分验证以下论文语义。之前把该验收作为继续研究的可靠基础时，遗漏了这些关键机制差异。现补充披露，而不修改或隐去旧结果。

## 2. 最优先：环境选择在当前第四章中实际没有筛选

位置：[CanonicalHmopso.java](../src/java/search/CanonicalHmopso.java:75)，尤其第93–97行。当前流程为：

1. 初群100个，四群互不重叠，总计仍100个。
2. 每个粒子完成QGS和局搜后只返回一个后代，总计100个。
3. 仅第三章加入旧种群；第四章直接从这100个中选100个。

所以PDDR-FF虽然被计算和排序，**没有粒子因这次代末环境选择而被淘汰，也没有局搜前候选靠该选择返回下一代**。它仍影响分群、pbest挑选和中央群局搜接受，不应误称整个PDDR机制完全没有使用。

相对地，[ClassicAlgorithm.java](../src/algorithms/classic/ClassicAlgorithm.java:75)中的NSGA-II每100个后代将父代与子代合成200个，再按非支配等级和拥挤距离保留100个。这是实际的生存选择。

### 论文与旧重建约定的冲突

已重新目视核对本地ESWA原文的以下页面：

- **p.7 §4.1：** 正文明确说明合并局搜前与局搜后的粒子，再依据PDDR-FF取前popsize个。
- **p.8 Algorithm 1：** 第16行只写从更新后的四群选择popsize个，没有明确保存和并入局搜前的四群，存在歧义。
- **p.10 Algorithm 3：** QGS内部确实执行状态转移并更新子群；不能把其50步当成只选leader、没有实际搜索。
- **p.14 Algorithm 4：** 另有下节中的明确更新规则。

旧重建选择了Algorithm 1的字面解释，并在《主算法论文一致性审查》的补充约定第7项登记，但未充分处理p.7正文的合并要求。**不能再把“第四章只有100个选择候选”说成论文唯一确定的语义。** 这属于最高优先级的基线重建缺口。

若按正文补齐，首先应考虑“全局更新后、局搜前的100个”与“局搜后的100个”组成200候选；它与NSGA-II的“上一代父代+新子代”不完全相同，不能简单混称父子代精英保留。

本轮使用冻结二进制直接执行零FE探针，确认：100选100保留全部粒子身份；200个候选中100个严格较好时，原PDDR选择器本身能筛掉差者。问题在候选池的构造，不是该手算场景下比较器把支配方向写反。

## 3. 更新算子也存在来源明确的非等价

论文p.14 Algorithm 4、Fig.6与当前[ParticleOperators.java](../src/java/search/ParticleOperators.java:29)对照如下。

|项目|论文|当前v2|性质|
|---|---|---|---|
|FA交叉片段|随机选两个位置并交换片段|随机起点后缀复制；MA同样使用后缀|已公开的重建选择，但不是等价实现|
|交叉/变异随机关联|每个guide生成r1/r2/r3，对应向量的交叉与变异复用相应随机数|六个判断分别重新抽随机数|边际概率可相同，但条件关联、组合事件和随机轨迹不同|
|非法资源修复|从合法机器/工人中随机替换|公共确定性取模修复|已公开适配；不能称论文原随机修复复现|
|WA交叉|片段交换后修复非法工人|只在相同位置FA一致时复制后缀WA，再修复|又一明确语义差异|

这些差异不意味着现在会产生非法解；本轮合法性与完整重解码均通过。它们说明“代码能正确解码、严格计费”不能替代“原算法搜索分布已实现”。其中片段与共享随机数应优先补充语义合同；修复的公共适配需保持所有方法共同规则，不能只为一方改动。

### 按位置更新与按工件继承，要单独归类

当前PSO先改JS，FA/MA/WA继续按位置解释，因此改变JS会隐式改变工件的资源绑定。NSGA-II的离散适配则先按job身份读取父本资源，生成新JS后再将资源写回相应job，见[ClassicVariation.java](../src/algorithms/classic/ClassicVariation.java:27)。

零FE探针在真实冻结JS引导方法上得到：JS从[0,1,2,3]变为[1,0,2,3]，位置FA仍是[0,1,0,1]，于是两个job的工厂绑定改变。**这种位置语义与原论文Algorithm 4一致，不应冒称实现bug。** 但它意味着基线与经典对照的变异核并不相同，NSGA-II的优势不能直接等价为“非支配排序优于四子群”。

“频繁重新绑定打散了有用的工件—资源结构”是有代码依据、值得检验的机制假设，尚未测得它在真实搜索中的净收益或净损失。

## 4. 公平性与结果有效性审计

审计证据目录：[nsga-gap-audit-20261102-102213-998529](../runs/nsga-gap-audit-20261102-102213-998529/)。

- 270次命令指向同一实例各自冻结的加工、SUT、疲劳输入，使用相同standby、精确增量开关及逐实例T；seed与登记一致。
- 所有算法经过同一RunContext/BudgetedProblem，初始化、全局和局搜均收费；逐阶段成功计数与总成功FE一致。解码结束后才发现超时的已完成解码，仍作为付费中断，不混入有效成功评价。
- 外部结果档案为同一无上限三目标非支配档案；每次成功候选都可入档，不只保存最终生存种群。因此“生存选择没保留好解”影响的是后续繁殖和引导，不能说好解一定从输出档案中消失。
- 原始121个冻结源码副本完整；当前与冻结版本仅有此前已登记的三个控制器恢复文件不同，Java搜索和指标未变。CanonicalHmopso、ClassicAlgorithm、DynamicRun冻结class与已验收工程产物一致，公共class位于classpath首项。
- 独立实现沿另一坐标轴作矩形HV扫描，重算270×3=810个分数，最大绝对差1.7764e-15；未复用原HV函数或其非支配过滤代码。
- NSGA-II最终选择的是预登记的常规配置0，并非通过校准选到特殊新参数；不存在本轮选中变异调参才形成该优势的情况。
- 既有工程检查在20_2_3_1、100FE下核对BASELINE、TAIL和四经典的返回档案编码/目标一致；源码也均从相同随机源调用100次共同createSolution。它没有保存全部六实例所有初代100个个体的逐次明细。SYNC/SHARE则按预先设计约束20个粒子，不能说九方法初始编码逐个相同；这部分由SYNC匹配消融控制。

**比较限制继续保留：** NSGA-II是共同模型上的明确离散适配；各算法自己的更新/选择规则不同。六个实例已经用于开发；校准只对经典登记三套设置，并非论文级对等调参研究；C*来自开发输出选择；没有逐时CPU/内存干扰遥测，短程JIT等不能完全排除。所有方法均为新JVM，同一运行时和固定时限；相同FE诊断与跨实例一致差距使单纯机器开销不足以解释现象。上述限制不等于已发现计费或指标错误。

当前56分38秒初筛仍有效描述**冻结v2配置**，既定停止扩量决定保留；不能把它升级为“完整论文基线必输”或“四子群方向不成立”。

原文实验报告500000次评价和静态插空/右移解码，本轮是共同动态追加式模型与短时间初筛，15000 FE只是途中诊断。原文Algorithm 1的enum只在代末增加种群数，未在该伪代码中逐次展开QGS/局搜计费；这不能证明作者真实实验如何计费，也不能据其表中优越性反推当前严格计费版本一定应当领先。不同问题/解码/预算的性能不能直接互证。

- SPEA2评价吞吐明显低于SHARE，但质量仍更好，进一步说明吞吐不等价于搜索效率。

- Q表按每群每次QGS重新初始化，探索概率0.8；动作频率接近分散分布。它是已登记的论文解释，不是本轮发现的失效bug；不能只凭频率认定学习无效，更不据此直接改ε重跑。

### 5.3 PDDR拥挤与选择假设的边界

PDDR-FF本身没有NSGA-II式拥挤距离。零FE探针证实，一组互不支配、没有其他被支配点的100个候选，其PDDR值全部为1，稳定排序不能区分其中的空间分布。该现象在当前“100选100”之外，提示补齐200池后仍需关注平局与多样性。

本轮没有保存每个时刻的完整活跃种群/父子候选池，不能据最终外部档案反推真实PDDR平局率、活跃种群克隆率或具体淘汰了多少优质候选；也不能把最终非支配点数量少直接当作活跃种群多样性崩溃证据。

同样，intra.accepted计数记录VNS外层接受事件，未计全部内层descent接受；不能用该数除以所有intra FE就声称“约96.5%局搜没有作用”。现有日志不足以计算逐候选真实收益率。

## 6. 四子群与共享应该怎样保留

有理由继续保留四个目标角色、粒子身份与pbest、可验证的工厂片段池及精确共享组合。当前SHARE相对SYNC平均+3.532%、中位数+2.074%、实质胜5/6，且自身共享维护约1.3%搜索时间；本轮20537次SHARE组合重算验证一致。这是值得带到更完整基线上的组件证据，移植后的收益仍需重新确认。

固定FA也没有锁死全体：只有四家族×五粒子=20个固定FA，另80个自由。SYNC与SHARE共同承担这个限制，SYNC对A0平均−1.559%，说明该组织方式有探索代价的信号；但混合了初始化与约束，不能据此量化“固定FA造成多少损失”。固定成员的跨厂FA修改在评价前会恢复，局搜意图受到限制；这不适用于自由80个粒子，也不是全部差距的解释。

后续应按以下顺序讨论，**本轮未执行这些修改或新性能实验**：

1. **先明确基线合同。** 对齐p.7合并池与p.14更新规则；v2原封保留，新解释单列版本。先验证候选池规模、父本只读、粒子pbest身份、FE与共享家族配额，不能把修正计作算法创新。
2. **保留四群角色，让生存选择实际发挥作用。** 优先检查局搜前后候选确实进入同一选择池；不要同时换成一套新全局算法。SHARE/SYNC必须随同一个基线重建版本迁移，维持匹配消融。
3. **把生成差与保留差拆开。** 下一轮若获授权，仅做一组固定配置诊断，记录已付费候选池、父本、存活者、pbest/全局档案更新时点和job资源绑定。先在同一已付费候选池上离线比较保留规则，区分“好候选未保留”与“候选本身不够好”；离线结果不能冒充替换选择器后的闭环性能。
4. **再决定是否改搜索机制。** 若语义补齐后仍落后，优先检验按job保留资源结构、跨群反馈节奏与精英/多样性保留中的单一因素，避免同时改算子、群额、Q参数和局搜频率。已有共享保持为受控组件，价值学习先保留为次候选。

不必因为NSGA-II暂时领先而放弃四子群，也不应为了保留框架而忽略这些来源和机制问题。当前最具体的下一项工作是补齐基线语义验收，而不是增加新模块或放宽原初筛阈值。
