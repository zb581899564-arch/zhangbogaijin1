## 原有额外评价量的来源

原始证据区第三章主路径 `perturbation` 第 2088 行写死 `QN=50`，第四章 `updatePosition` 第 974 行同样写死 `QN=50`；工作副本归一时曾改成读取 Qnums，但这并未消除其他算法问题。

两章旧 VNS 一次调用实际为四次 VND，每次六个邻域，每个邻域同时重评候选和已评价的 incumbent，即 `4 × 6 × 2 = 48` 次解码。因而第三章一代仅工厂内局搜就消耗 `100 × 50 × 48 = 240000` FE，再加初始化和整群重评可解释此前测得的 240400 FE。这个量与 `QN × swarmSize` 的内部估计计数明显不同。

第四章原全局 QGS 为各群合计 `QN × N` 次解码，工厂内 VNS 又额外消耗 `48 × N`；其余初始化/整群评价仍另计。具体运行 FE 不能用一个固定公式代替真实调用计数，尤其遇到预算中断、候选无变化或异常时。新的唯一证据是 `RunContext` 记录的实际 decoder attempts；同一个编码的重复解码仍消耗 FE。

## 重建实现与论文构件的对应

| 组件 | 实现 | 来源与行为 |
| --- | --- | --- |
| 主循环与阶段顺序 | `CanonicalHmopso` | 四群全局搜索全部完成后再做局搜。JMS 按 Algorithm 1 先完成全体 inter，再做全体 QLS；ESWA 按 Algorithm 5 对各粒子执行 inter→intra。 |
| PDDR-FF、非支配关系 | `ParetoTools` | 三目标最小化，严格支配，`q + 1.0/(p+1)`；目标相同不会互相支配。初始化保存真实 ND 集。 |
| 三边界加中央群 | `CanonicalHmopso.decompose` | 以 Cmax、TEC、TWC 分配边界配额，中央群按 PDDR-FF 排序。实现使用互不重叠的粒子身份，详细分配顺序见下节公开约定。 |
| 粒子自己的 pbest 与全局 gbest | `Particle`、`SearchState` | 每个粒子携带个人 ND 历史；按当前方向挑自己的引导解。搜索 gbest 由初始化和代末选中粒子的个人历史构建，代中冻结，避免执行顺序引入额外异步引导。 |
| 四向量 PSO | `ParticleOperators` | 随机 JS 交换、交换序列向 pbest 和 gbest 引导，再进行 FA/MA/WA 交叉变异；只写 child，父粒子及两个 guide 均不修改。 |
| 工厂间局搜 | `LocalSearch.inter`、公共 `FactoryNeighborhoods` | 依据真实工厂指标选高/低负荷工厂；交换与插入；边界群按本目标、中央群按共同参考池中的 PDDR-FF 接受。改善后重启。 |
| 第三章 QLS | `LocalSearch.improveIntra`、`QTable` | 每个粒子单独两状态、F 动作表；动作选择一个工厂，VNS 后继续从结果出发；奖励为边界目标改善或中央三目标相对改善和。初态为 1，Δ>0 才进入状态 0。 |
| 第四章 QGS | `CanonicalHmopso.qgs`、`QTable` | 每群独立两状态、三动作表；保留前次 leader、当前群最佳、global ND 集二元锦标赛。奖励为群平均改善，Δ≥0 进入状态 0。每次 Algorithm 3 初始化新表。 |
| 九邻域工厂内搜索 | `IntraNeighborhoods`、`LocalSearch` | 第三章为 JS/MA/WA 各 insert/reverse/swap；第四章为 JS 三算子、MA/WA 各按负荷或能力重分配及交换。shake 和 VND 均执行实际评价；接受改善后重启。 |
| 严格预算及外部档案 | `BudgetedProblem`、`RunContext` | 初始化/global/inter/intra 均只调用同一个包装问题。外部档案接纳每次成功评价，包括后来被搜索拒绝的候选；它与用于搜索引导的代末 gbest 分开。 |

另有以下无法从论文唯一确定、但必须固定的实现细节：

1. 分群不复用粒子身份，按 Cmax→TEC→TWC 顺序从剩余粒子分配边界配额；中央群取其余粒子并按 PDDR-FF 排序。相同分数保留稳定输入次序。不同的配额重叠规则需另列变体。
2. Q 相同的最大动作均匀随机打破平局；第四章初态取 1，首次执行“保持前次 leader”而尚无历史 leader 时，使用当前群最佳。表的初始化时机遵循 ESWA Algorithm 3；不宣称跨代 Q 值持续积累。
3. 中央群局搜将本轮全局更新后的种群加 incumbent/candidate 作为共同 PDDR-FF 参考池；临界工厂目标在三目标中均匀选取。这与公共 factory helper 的既定规则一致。
4. FA/MA 采用单点后缀复制；第三章 WA 在同一工厂排列块中保留 donor 片段并补齐其余工人，变异用相邻交换；第四章 WA 只在 FA 相同的位置复制，变异从该工厂合法工人中重选。所有父本只读。
5. 第四章负荷邻域以第一阶段编码对应的工件数作为机器/工人负荷，能力邻域用该阶段速度/效率，从最弱的已使用资源转向最强资源；没有增加未编码阶段的隐藏基因。
6. 不合法资源索引使用公共确定性 repair 处理；论文部分操作描述使用随机修复，两者不能视为逐随机调用相同。中央相对奖励遇到合法的零目标值时，将该分量分母设为 1，避免 NaN；当前常规实例的正目标不触发此规则。
7. JMS 的环境选择明确使用父代与最终局搜子代并集；ESWA 依其 Algorithm 1 从四个更新后的群中选 N 个。个人 ND 历史随粒子身份一起保留，不按数组位置错配。
8. 非支配档案不设容量上限，目标完全相同保留第一代表。外部档案、编码修复、内部 pbest/gbest 管理都计入墙钟时间；只有真正进入解码器才计 FE。两章仍各实例/seed 独立 JVM、单线程运行。

以上约定及实例缺失的 setup/standby 数据补充方式共同决定当前基线。正式比较前需要固定完整配置、数据来源和代码版本；不能直接以“HMOPSO-QLS/QGS 原论文复现”省略这些条件。
