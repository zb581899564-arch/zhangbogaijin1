## 首轮发现的问题及证据（当前处理见v2验收）

### S01：三个目标与四个工厂索引混存

两个活跃问题类都声明 7 个目标。实际 makespan、energy、worker cost 存于下标 `0, 1, 6`；下标 `2–5` 存局部搜索用的关键工厂索引。通用 `DominanceComparator` 遍历全部 7 维；通用拥挤距离、排序和指标也需要逐一追踪。

已构造反例：解 A 在三个物理目标上全部优于 B，仅辅助工厂索引更大，通用比较器却返回互不支配。这已验证存在语义风险。不能将各算法内部手写的 `0,1,6` 比较与通用七维比较混为同一评价准则。

后续应将辅助信息移至有名称的属性，建立真正三目标的规范基线，再让经典算法和新方法共享相同的解码与目标接口。需要同时检查所有旧代码读取下标的位置，不能仅把 `setNumberOfObjectives(7)` 改成 3。

### S02：评价预算与内部循环不能直接用于公平比较

短程诊断以 wrapper 记录每一次 `problem.evaluate`：配置上限均为 200，但第三章实际评价 **240400 次**，第四章 **10000 次**。这只是本次所选小实例与诊断参数下的计数，不能外推所有配置。

第三章 `MOPSODivSubDE` 中仍存在 `QN = 50`，第四章也有 `QN = 50`、以及覆盖传入参数的 `QN = 5`；局部搜索中额外评价没有形成全局严格预算。E07 只修正外层上限传参，尚未解决全局 FE 问题。

后续统一评价服务，统计初始化、全局、工厂间、工厂内搜索全部 FE；在评价前检查剩余额度，并规定最后一次局部搜索的截断和返回行为。同时间比较也单独开展。不得用当前外层计数冒充 FE。

### S03：随机源与实例静态状态

存在多处 `new Random()` 和无显式随机源的 `Collections.shuffle`。设置 `JMetalRandom` seed 并不能控制全部随机数。机器数、工人数、阶段工人池等还通过 static 共享。需统一 RNG 并去除实例间静态耦合后，才能宣称同 seed 可复现或安全并发。

### S04：第四章代码与已发表版本不完全一致

- ESWA PDF 第 7 页 §4.2 表述 WA 长度为工件数，现有代码为 `jobs × stages`。
- ESWA 的模型使用独立标准设置时间 `SUT[j,k]`（PDF 第 5–7 页）；现有实例仅见机器、处理时间、工人数、熟练度和成本等字段，没有独立 SUT 数据块，解码多处以 `processingTime × 0.1` 生成设置时间。
- 期刊方程中加工、设置的资源占用及速度换算需要与代码逐项核对，不能仅因代码包含 setup 片段即认定一致。

这可能同时包含版本修改和缺失数据，不能无来源补造 SUT 或套用任意分布。应先确定期刊版/硕士论文版两条合同，并构造表格小例的手算结果进行验证。

### S05：解码正确性、局部搜索和对比算法仍需专项核对

本次检查能发现部分存储和计算不稳定问题，但没有导出每道工序时间轴，尚未独立验证机器不重叠、工人不冲突、工序先后、setup 与加工分离、右移策略不改变 makespan，以及 TEC/TWC 与论文算式一致。经典算法、其余 Builder、旧批处理输出和质量指标都尚未全部验证。

完成这些工作之前，不将旧输出作为本副本的公平比较结果，不宣称整个原始代码已补齐。
