# 成熟接收状态与全局／共享供体增量结果

结论：**工程与可复算性通过，普通供体合并没有达到继续投入的综合质量信号，停止扩大本版本。** 保留原四职责、QGS、家族及已有共享机制；本轮不修改默认主线，不启动新Goal、更多seed或完整算法实验。

本次是成熟状态上的一次条件性局搜探针，不是每臂50万FE的新算法排名。它回答“给定同一批已经付费的全局候选，额外开放供体渠道有没有增量”，不能回答“生产这些供体是否值得”或“全局搜索应当删除”。

## 先确认没有把旧失败换名重跑

详细规则见[事前协议](成熟接收状态与全局共享供体隔离协议-2026-11-06.md)。旧GRAFT已经试过外部付费供体，不将外部池包装成新创新：旧试验从初始解重启普通PA，使用独立来源的静态ND100；本轮从同一SHARE_CTX_GOM轨迹提取成熟的100个接收者，固定原局搜模型、角色、家族、接受规则和已付费档案，只改变G/S来源的可见性。它也不重复改变首轮入口的PRE_FIRST，或改变已完成局搜状态可见性的ALL/OWN/SYNC。

源为两个开发实例20_8_5_1、100_2_3_1及三个已有seed：16110003、16110037、16110069。按首次PRE_GLOBAL且FE≥250000选窗，实际入口分别为255880、273560；随后5000次全局候选及其已付费档案A0用于探针，不读取更晚结果。六条源重放完整50万次与上一轮Linux FULL的初始解、整条付费摘要、公共检查点完全一致。

四臂为R（原实时局搜供体）、G（R加普通全局供体）、S（R加共享组装供体）、UNION（普通R+G+S合并）。每臂同一100接收者完整轮，20例3820FE、100例19860FE。工作态R保持实时更新，外部供体冻结；模型只从原接收者学习。每次提议独立派生抽样种子，避免不同池大小改变后续公共随机流。这是隔离抽样接口，不冒称原生算法自然续跑。

100例UNION/R的三个seed均为“HV略升、IGD+变差、C差反向”。其配对C差中位−11.5525个百分点，范围−12.0956至−10.5471，达到事前需要重点解释的退化界限。HV提升远低于1%，不能抵消IGD+与覆盖退化。20例UNION/R三个seed的HV均下降，但量很小。

共享相对普通全局池的条件增量UNION/G：20例HV与IGD+配对中位均0；100例HV仅+0.003981%，IGD+中位0。全部五项预登记比较均报告，没有挑选有利控制。

参考点1.25、1.5、2.0下，UNION/R的**中位**HV方向一致：20例均负，100例均微正。但100例seed16110003在1.25时为−0.035397%，在1.5时为+0.053279%，单seed方向会翻转，不能声称每条轨迹都对参考点稳健。

工作种群也没有被略去：UNION/R在20例的HV中位+0.1842%、IGD+−1.5207%、C差−6.8989个百分点；100例为HV+0.0763%、IGD+−8.8625%、C差**+8.9757个百分点**。这说明100例的工作态覆盖有局部价值，但指标仍冲突，且未转化为末档案综合优势。它不能作为全面失败或全面成功的单一证据。

## 机制实际上有没有触发

共享只向固定家族CENTER提供候选，free80没有S来源。S臂各上下文实际读取共享供体：20例364–450次、100例2359–2841次，已充分触发；不能把没有明显增量解释成“根本没调用”。

普通UNION中，G约占97%的抽取，R约占2%；原有效局搜供体会被大量G候选稀释。因此本轮识别的是这个**普通合并规则的净效果**，不是G候选的固有价值。20例seed16110037在UNION中只读取S10次，低于预定20次，此上下文的“已有G时再加S”标为触发不足；S单独加入的同一上下文则读取364次，二者不能混为一谈。

本轮没有证据证明四子群能通过这条额外供体渠道提供独特增量，也没有否定原共享生成机制此前已有的收益。不会根据此次稀释现象立即调来源比例、池容量或窗口追正结果。
