# FA统计来源验证：评价前冻结协议

实例100_2_3_1、源seed14910003。承接《FA统计来源最小验证方案》，三入口104540、179120、228840及其QGS前FA统计来源不变。只在Linux隔离目录执行；不重跑来源轨迹、不改主线或扩量。全部批次完成后才看质量。

## 固定处理和抽样

- POST_FA：上一轮代数重建的真实POST模型，须与原POST矩阵/FOS逐项相同。
- PRE_FA_STATS：只替换FA统计来源，保留真实POST顺序内部项、80样本、工厂数、2/3权重及聚类。
- RANDOM_FOS：对PRE树用一次固定随机工件重标号，逐节点保持大小及树结构；所有父代共用该入口的同一置换。
- 四职责各取原POST自由成员中槽号最小的两个父代。每父代抽16个不重复非平凡合并序号（原199节点中的100至197，排除100叶和全体根）。三臂对应序号、供体槽完全相同。
- 派生流为SHA256(`fa-stat-query-v1|14910003|入口FE|原槽号|用途`)前8字节大端整数，供Python3.11 Random使用。用途分别为merge-indices、donor-indices、job-permutation；置换槽号固定-1。派生流不是新增优化seed，不选择或重抽。
- 掩码内同时复制同一原POST供体的完整FMW与顺序键，沿用原PaMixingMove空厂回退，恒等、重复和回退均收费。固定父代、供体和模型，候选互不推进工作态。

## 零评价关

先构造全部1152个未评分候选及24父代QA输入。每入口PRE相对POST物理排程变化至少26/128，且涉及至少两个职责；三个入口都须通过。不通过即整批停止，新增评价/QA为0，不重选父代、序号、置换或入口。

独立逐字段核对候选生成、随机树关系和大小，再用已冻结Java PaMixingMove零评价夹具核对全部1152提案。全部通过才做24父代完整QA，目标逐位一致后才评价候选。

## 预算与接受语义

科学查询最多1152次实际尝试：三入口×8父代×16提议×三臂，各臂每入口128次。完整QA最多24次，无其他新解码。沿用已验收完整评价入口及共同RunContext；按旧入口单批上限分批、单JVM顺序，不增加旧单批上限。失败保留账目和最后有效输出，不补量。

主统计包含所有付费候选，与共同外部结果档案的口径一致。另按原接受公式记录每个候选相对固定父代/请求前S档案的wouldAccept：M/E/W对应目标严格改善；CENTER为弱支配父代，或不被请求前档案严格支配。每个候选独立，原接受公式不变，档案不在候选之间更新；该标记不反馈搜索，接受子集结果单列。没有把固定父代查询当成live局搜。

## 评分和取舍

主背景为请求前S全付费档案，辅助背景为同期S∪PA档案。归一化沿用旧尺度，HV参考1.5，敏感性1.25/2.0。统一距离参考为三入口S档案和全部新候选的经验ND并集，仅离线使用；辅助背景另用三入口S∪PA和全部候选的共同ND参考，单独标注，不拼接距离数值。IGD+/IGD均报告绝对值和对称改善；精确弱支配双向C附覆盖数/分母。

对POST_FA和RANDOM_FOS分别判断：至少两个入口PRE有HV≥0.1%或IGD+对称改善≥5%的信号；其他入口无HV下降超过0.1%、IGD+恶化超过5%或双向C覆盖差反向超过10个百分点。信号入口HV在1.25/2.0参考下不得反向。指标有小分歧如实保留，不多数投票或加权。

两个比较都通过才保留“FA统计来源”这个有限候选容量假设。只有一入口正信号或仅胜原控制，记录为不足/普通控制可解释，不晋升。辅助S∪PA只用于分辨追及与额外区域：本轮没有导入PA解，追及已知PA区域可以有搜索价值。即使通过，也不直接改整算法或扩大实例/seeds；后续live程序须另立协议。

三入口是单轨迹相关时点，不冒称三个独立seed。记录实际类/源码/依赖/输入身份、JDK/Python、FE/QA及过程耗时；本轮不作同时间优势结论。
