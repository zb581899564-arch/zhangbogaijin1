# 后续七步计划：动态疲劳下的四子群联合重组

日期：2026-11-01。状态更新：前三步已实现并通过必要正确性及完整搜索联调，见[验收记录](前三步实施验收-2026-11-01.md)。第四、第五步已完成540次完整运行及统一分析，见[结果](第四五步结果-2026-11-01.md)。SHARE有独立共享收益信号，VALUE尚无稳定独立同时间优势，正向交互未获支持。第六步尚未启动；下文保留原定顺序与范围。

经典算法接入后的扩大决策先按[扩量初筛标准v1](实验比较协议.md)执行：规则已制定，执行清单待工程验收后冻结，尚未开始新运行。初筛270次限时试验，统一取FE快照，预计搜索39分钟、总性能初筛上限90分钟；绿/黄/红仅用于当前配置的资源投入，不作期刊或整个分群方向的资格判决。

## 当前主线与范围

按本轮上下文，将基本版本确定为：李明哲第四章双资源分布式异构混合流水车间问题，加入动态疲劳积累、空闲恢复及疲劳对持续时间的影响；主目标保留 Cmax、TEC、TWC。累计疲劳暴露、峰值疲劳作为辅助分析量，不在本轮计划中替换第三目标。

保留 HMOPSO-QGS 的三个边界子群和综合子群，以及真实个人历史、原 Qg、选择和档案机制。主候选方法是在其粒子更新中加入“精确一步转移＋学习型余程价值”的有限块四向量联合重组。增强群间共享与组合作为后续支撑机制。首版保留共同的普通局部搜索。

不重启旧伴随排名的调参，不同时引入新 Q-pbest、群级六宏动作 Q、PF-SDST、主动休息或后阶段新编码。它们不是本计划的必做步骤。

本计划更新后续工作顺序，不覆盖 v1–v10 历史原始证据。那些结果的对象是具体局部机制或搜索链，没有验证本次新生成器与完整四子群方法。此前贡献审查的结论不得扩大为整个分群研究的结论。此前三篇近邻的本地方法正文已在本轮定向阅读中补查，仍不称穷尽查新。

设计细节见 [收敛讨论稿](research/2026-11-01-方案收敛/收敛方案-讨论稿.md)，文献边界见 [资料阅读记录](research/2026-11-01-方案收敛/资料阅读与设计依据.md)。两份讨论稿保留形成时的未决项，以本计划的主线选择为准。

## 七步总览

| 步骤 | 工作 | 交付与回答的问题 |
|---|---|---|
| 1 | 固定动态问题和解码语义 | 新模型合同、来源与差异表：究竟解什么问题 |
| 2 | 建立完整动态四子群基线 A0-D | 可重复运行的共同基线：完整流程与计费是否可靠 |
| 3 | 实现最小联合生成器及轻量余程模型 | 可重放子代、共同候选控制：机制是否正确实现 |
| 4 | 第一轮完整算法试验 | 同FE与同时间曲线：联合结构和学习各有什么作用 |
| 5 | 检验四子群增强共享及交互 | 2×2对照：组合后是否出现独立或条件性收益 |
| 6 | 正式比较、消融和泛化 | 多实例多seed证据：收益是否稳定、边界在哪里 |
| 7 | 整理论文与可复现实验包 | 贡献、公式、伪代码、图表与代码证据对应 |

步骤1–3完成正确性与工程基础；步骤4给出第一次完整算法收益判断；步骤5回答四子群协作整合问题；步骤6–7形成论文所需证据与材料。步骤不是要求结果必须为正的“通过关卡”。

## 第一步：固定模型和解码边界

### 做什么

1. 另立动态模型版本，不改写原静态模型合同。保留工厂/阶段资源结构、工人全工序占用、设置时间和第四章计薪口径。
2. 冻结疲劳积累、恢复、开始疲劳影响持续时间的公式；说明设置时间是否进入同一疲劳修正及工作区间，与现有原型保持可核对关系。冻结参数来源和生成规则。
3. 四向量仍为首阶段显式决策；按工件身份处理资源归属，明确后阶段排序、资源选择与并列规则。
4. 首轮采用已讨论的确定性追加式疲劳解码，无插空、右移、主动休息或硬疲劳上限。它是共同的解码策略，不能称为原解码完全保留，也不能声称覆盖所有可行含等待日程。以后如适配插空/右移，需另立共享版本再比较，当前不将其作为首版前置研发任务。
5. 冻结SUT、standby、合格实例边界和重建来源。将已反复观察的36实例标为开发资料；在正式确认前建立未参与选型的实例/参数种子清单。
6. 固定主目标Cmax/TEC/TWC，疲劳辅助量不改变接受和档案规则。

### 完成标准与产物

产出独立动态模型合同和“原论文—静态重建—动态共同解码器”差异表；给出可手算的恢复、加工、能耗、计薪锚点。所有对照共享相同的动态评价语义。

β=0应退化到相同追加式解码器的无疲劳时长反馈版本，不要求等于带插空/右移的原静态A0。模型变化与算法变化分别比较。

## 第二步：建立完整动态四子群基线 A0-D

### 做什么

1. 在现有Java受控入口接入共同动态转移内核与解码器，保留原静态A0。Python原型用作共同数值输入下的独立核对，不跨语言直接比较运行速度。
2. 完整运行初始化、四群分解、真实pbest/gbest、原Qg、基础更新、原普通局部搜索、环境选择和档案；复用已核实行为，不把一次局部链当作基线。
3. 扩展公共精确增量：支持改变per-job FA、源/目标工厂变更、严格相同前缀复用与受影响后阶段重算。旧固定FA缓存不能直接冒用其验证结论。
4. 建立预算和计时接口。初始化、候选评价、拒绝子代、训练、推断、缓存、档案等均按共同规则记录；一步候选试算另记数量，完整目标评价计FE。

### 最小必要验证

- 资源可行性、三目标与时间轴对齐；相同输入及seed可重复。
- 同一编码在Java/Python共同输入下的数值结果一致；不同实现比较允许事前规定的数值容差，不凭空要求跨语言逐位相同。
- 同一实现内完整与增量重算对齐，包括跨厂迁移和并列顺序变化。
- 预算在初始化、全局、局部阶段耗尽时返回已完成评价的合法结果；未完成评价不补造目标。
- 同FE固定随机路径比较完整/增量版本，确认加速没有悄悄改变搜索语义。

### 完成标准与产物

交付可运行的A0-D、必要正确性证据和费用基准。所有新方法与内部对照共享验证过的加速，不能把公共重算提速归到价值学习贡献。

此时只说明可靠的动态完整基线已经建立，不说明算法创新有效。

## 第三步：实现一个最小联合重组器

### 做什么

首版仅替换部分全局子代生成机会。起跑配置暂用b=4、每步候选c≤6、指导概率rho=0.25；实现前冻结，不靠多轮筛值追正结果。小于块长的实例按合法规模截断。参数不是已证实最佳值。

拆分职责为：前缀状态、候选提议与可完成性、一步转移、特征、价值回归、编码写回、费用记录。避免把这些逻辑塞入一个搜索函数。

关键接口：

- 恢复真实前缀，冻结父本/pbest/gbest及本批学习参数。
- 候选为合法(j,f,m,w)完整元组，候选提议不先完整评价。
- 每个动作后更新与当前前缀相容的补全见证；每厂非空检查最终可完成性，允许合法跨厂交换的临时空厂。
- 精确一步代价为当前目标前缀的差分；余程覆盖剩余块、固定首阶段后缀以及全部后阶段。
- 首版固定低维线性方向价值模型，用一批已完成子代轨迹的蒙特卡洛余程作有限回归更新；新余程目标不折扣，原Qg折扣保持原语义。
- 所有选择写回四向量，正式评价器不读取学习参数；被拒绝但已完整评价的合法子代可以训练。

同时实现共享候选接口的随机、一步贪婪与非学习尾程估计控制。尾程启发式的具体公式在观察试验结果前冻结，不称未经证明的量为严格下界。

### 完成标准与产物

交付可插入A0-D的生成器与控制版本。验证合法补全、父本不变、构造/固定解码重放一致、跨厂资源编号、疲劳/费用累积、批次冻结和预算中断。

做一次有界的同前缀候选诊断，记录真实动作regret、排序及候选覆盖。离线真实补全不反馈搜索并单列费用；该诊断不能替代下一步完整算法试验。

## 第四步：尽早运行完整算法，判断主机制价值

### 五个核心版本

| 版本 | 定义 |
|---|---|
| A0-D | 完整四子群＋共同动态模型 |
| J-Random | 同一联合生成器，随机合法动作 |
| J-Greedy | 同一联合生成器，只看一步精确成本 |
| J-Tail | 同一联合生成器，加冻结的廉价非学习尾程估计 |
| J-Value | 同一联合生成器，加学习型余程价值 |

除A0-D没有新块生成器外，其余版本具有相同块选择、候选提议与调用概率；所有版本保留共同原局部搜索。不同运行轨迹自然分叉，同候选规则不等于每一步候选完全相同。

### 初筛规模与预算建议

- 从开发资料中事前按小/中/大规模、资源紧张程度选择6个实例，使用5个新算法seed。
- 五个版本各做同FE和同时间两种试验，计划量为6×5×5×2=300次完整运行；本轮已按冻结协议落实，其中第四步300次，第五步另增240次。
- 实际FE与时间预算先在工程校准中确定，足以覆盖多个完整更新批次与学习启动期，随后冻结。不能照抄此前局部链0.5/2秒预算。
- 每次限时运行预先设定早、中、末检查点，直接得到HV(t)和IGD+(t)，不为观察三个时点额外重复三套试验。
- 先验证正确性及真实费用，再完成整个冻结初筛；除错误、预算失控或资源问题外，不看到某个有利时点就提前结束。

### 输出与解释

交付实例层配对结果、前沿质量随时间变化、真实完整评价数、训练/推断/恢复/解码成本、独立子代样本数以及各方向表现。5seed初筛仅作选型证据，不是最终显著性结论。

分别回答：

1. J-Random是否改善A0-D：联合候选/表示是否有价值？
2. J-Value是否改善J-Greedy、J-Tail与J-Random：学习是否有增量作用？
3. 同FE信号能否在同时间下保留：额外成本是否值得？

若结果不理想，先区分候选缺好动作、标签/特征不足、启动样本不足和额外费用，基于记录做一次针对性解释；只修复可证实的错误或验证有依据的单一假设，不无限换seed、预算或块比例。

这里不把单用无优势写成“整个四子群方案失败”。若存在事先明确的共享交互假设，第五步仍可进行有界验证；若只想扩大同一无效配置，则不直接升级到正式大试验。

## 第五步：验证增强四子群共享与主生成器的配合作用

### 做什么

冻结小比例同FA上下文家族、整厂方案池和综合群组合规则；按工件身份固定FA。上下文包括完整工件集合、实例参数、初始状态及解码规则，不能把旧厂方案贴给新工件集合。保留自由区的跨厂探索。

因为本计划保留TWC，需要调整原来的R版组合：在Cmax上限T下，对给定非负权重η，逐厂选取满足c_f≤T且使e_f/s_E+η·twc_f/s_W最小的方案。这在无跨厂耦合和匹配上下文的有限池内可分解；它不是“全局工资预算约束”的等价解，也不保证找到非凸Pareto前沿或支配父本。T与η取值规则先固定。

完整目标、组合费用和档案访问均计入共同预算。不先启用新增群级Q或协作信用控制器。

### 对照

| 版本 | 新生成器 | 增强共享与组合 |
|---|---|---|
| B0 | 无 | 无 |
| B1 | 无 | 有 |
| B2 | 有 | 无 |
| B3 | 有 | 有 |

B0/B2尽量复用第四步相同冻结协议下的有效结果；协议、实现或预算变化时不可直接拼接。增加必要的“只同步FA上下文、不开池组合”控制，区分家族约束本身与共享组合的作用。

### 完成标准与产物

交付B2-B0、B3-B1、B1-B0和交互差(B3-B1)-(B2-B0)的实例层效果及费用。若B2弱但B3相对B1有收益，可以支持“生成器依赖共享上下文的条件性作用”；不能把全部收益自动归给B1，也不能只凭B3优于B0说两个部分都有效。

局部块修复是本步的可选扩展：仅在全局/共享配置明确后，把同一生成器替换少量原局部搜索机会，与同FE/时间的原局部搜索单独对比。它不是必需新增贡献；没有独立作用则保留原局部搜索。协作信用可作来源诊断，学习化另立假设，不是本计划强制增加的模块。

## 第六步：正式性能、消融和泛化

选定最终机制后，正式运行前冻结参数、调优预算、主比较、统计方案、实例种子与预算。

### 必要比较

- 动态共同基线A0-D；公平适配的NSGA-II、SPEA2及第三个经典方法。
- 按本地正文差异选取可合理适配的近期强方法；明确改了哪些目标、表示或解码，不把不同问题原论文成绩拿来排名。
- 保留最强的普通/非学习内部控制；主方法的代表性消融。

### 需要回答的机制与适用范围

- 去掉价值模型中的疲劳特征，但保留真实动态物理，检查学习层疲劳信息的增量。
- β=0与动态疲劳；比较不同积累/恢复和资源紧张条件。参数由事前设计决定，不筛选让算法获胜的疲劳强度。
- 必要时比较实时子代前缀特征与固定父本特征，检查闭环状态的作用；两者始终用真实共同解码器评价。
- 小/中/大规模和更长时间预算，观察启动费用、持续收益与退化区域。
- 报告Cmax/TEC/TWC的极值和权衡，累计/峰值疲劳仅作模型内辅助量，不外推医学意义。

主指标为同时间HV(t)，IGD+(t)作关键辅助，补充同FE、达到事前指定质量的时间、吞吐及尾部退化。参考点、归一化与经验参考集规则共用并事前冻结。

正式重复数根据开发方差和统计设计确定。配对以实例为单位处理，seed是同实例重复，不冒充独立实例；处理多重比较并给出效应和区间。正式确认实例不得参与调参；仅更换算法seed不构成实例泛化。

### 完成标准与产物

形成可支持或否定具体主张的完整结果包，包括失败、无效、退化、费用和适用范围。研究完成不以所有指标均获胜为条件；论文主张必须与实际结果对应。如果缺乏可重复的机制收益，则记录不支持范围并重新评估选题，不为凑论文添加更多模块。

## 第七步：论文与可复现材料

模型和方法章节可随实现同步起草；正式效果表述在第六步后确定。

最终交付：

- 问题定义、公式、原模型差异和数据重建来源。
- 完整四子群算法伪代码、联合生成器、学习目标及计算成本。
- 合法补全、固定编码重放等必要性质，以及有限池组合性质的适用条件。
- 原始前沿、完整配置/seed/预算、共同指标计算、同时间曲线、消融与局限。
- 可运行代码与实验说明；实验图表与原始结果一一对应。

以ESWA为目标准备，具体投稿与对外发布另按用户后续要求处理。基线工程修复、公共增量加速和通用价值公式不冒充各自独立算法创新。

## 各步完成后的汇报格式

每步汇报四件事：实际完成的文件/程序；通过的相关验证；能够支持的研究结论与边界；下一步具体工作。结果不支持某个组件时说明组件与条件，不上升为整个四子群方向的笼统否定。

实施顺序为1→2→3→4→5→6→7。文献差异整理与论文方法记录可伴随推进；不再为形式上的步骤反复重跑旧v1–v10，也不在本轮计划阶段提前报实验完成。

前三步及第四、第五步开发初筛已完成。下一项建议是为SHARE、强普通控制及VALUE消融制定第六步独立确认协议，重点核对两例退化、固定FA限制、疲劳场景、长预算与强算法比较；尚未启动新实验。论文主张按本轮实际结果收敛，不将组件无优势扩大为四子群框架失败。
