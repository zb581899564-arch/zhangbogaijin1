# 实验比较协议（三指标联合报告v2与历史扩量初筛标准v1）

**2026-11-05生效修订：** 依据用户明确要求，后续综合HV、IGD+、双向C评价表现和决定推进；不能只凭HV概括优劣。[三指标联合比较规范](三指标联合比较规范-2026-11-05.md)规定双向C口径、逐seed与实例层汇总、指标分歧和新协议登记要求。下面已冻结的扩量初筛v1及各旧运行保留历史身份和原停止决定；追加三指标解释，不倒改旧判定。

本协议规定后续证据要求。旧七步计划第四、第五步开发初筛已完成；[七步计划v2](后续七步计划-2026-11-01.md)将其归入新版第3步开发证据。2026-11-02新版第4步经典接入已验收，第5步270次扩量初筛已完整结束；两个冻结配置未满足扩量条件，第6步按停止分支未启动正式独立确认，见[实际结果](新版第5步结果与第6步分支-2026-11-02.md)。下文扩量初筛v1是新数据产生前的算力投入决策标准，不是论文贡献或期刊资格审查。一次启动、短程诊断或原材料中的旧结果均不构成新方法有效性的证据。

## 比较对象和共享边界

- 当前规范重建基线：A0-sourced-reconstruction-v2。三目标、预算、RNG和时间轴已验收，论文歧义/参数与缺失数据的补全方式必须随结果公开；不冒称作者原成绩复现。
- 若在 A0 上加入增强，命名为 A1，单独记录增强内容，不能继续冒称原论文算法。
- 新方法单独命名，并与 A0、A1（若存在）及适配后的 NSGA-II、SPEA2、MOPSO 等比较；相关近期强方法在文献检索后确定。
- 共享同一问题、实例、合法表示或有明确成本的修复、解码器与物理目标。经典算法不共享新方法专用的分群、引导、强化学习或局部搜索，除非另列为增强变体并公开标记。

## 预算和重复

- 同 FE 和同墙钟时间分别报告。FE 包含所有初始化、全局搜索、局部搜索、候选拒绝和修复后评价；缓存命中及其成本单列。
- 外部全评价结果档案与内部搜索引导档案分开，所有比较方法采用相同结果档案口径，档案开销计入时间。
- 固定模型版本、SUT来源/生成seed、standby和实例资格清单，原论文成绩不与重建数据直接横比。
- 总预算、种群、参数调优预算和硬件/线程规则在最终比较前固定；同时间比较使用同环境，控制并发干扰。
- seed 控制全部 RNG。开发与最终测试实例/seeds 分开，逐实例多 seed 重复；正式重复次数依据方差、统计设计和成本事先确定，不能看到显著结果即停。
- 每次运行保存版本、配置、seed、真实 FE、时间、目标向量、原始非支配解及失败信息。当前受控入口已满足严格搜索FE和统一RNG；返回解离线QA的额外解码次数单列，不能混进搜索或隐藏总费用。

## 指标和统计

- HV、IGD+、双向C共同报告和解释；HV越大、IGD+越小越好，C(A,B)和C(B,A)同时呈现。三目标均按最小化处理，不以某一集合指标代替其余两项。
- 归一化边界和 HV reference point 在最终比较前冻结，全部方法使用同一套。经验参考前沿的构建规则、来源与是否混入最终测试输出要预先公开。
- IGD+ 使用独立参考集或事先约定的统一经验参考前沿；无真前沿时明确其近似属性，避免声称绝对最优。
- C采用精确弱支配，目标向量去重，相等计覆盖；双向覆盖不互补，无覆盖不等于质量相同。报告覆盖点数与分母，空前沿不伪造C值。
- 指标一致且达到事前幅度/稳健性要求才称综合优势；有分歧则明确权衡，不作任意加权总分或三项多数投票。新协议事前登记三个指标的实质改善/不劣界限及分歧处理，不强求每项都严格获胜。
- 传统 IGD、三目标极值、attainment/EAF、尾部退化和计算开销按具体问题补充；不以单一 makespan 最优值取代多目标比较。
- seed 层面报告分布与效应大小，在实例层面做配对统计并处理多重比较；不把相关的同实例重复当作独立实例。

## 可归因证据

消融区分新机制、编码/解码变化、局部搜索强度与额外 FE。所有失败、退化、预算超限和无效实例如实保留。新方法要说明何种实例结构下有效，不能只展示最佳 seed、最佳实例或胜弱控制。

## 扩量初筛标准v1：判断是否值得投入大规模实验

制定日期：2026-11-01。**本节的判断规则在新初筛结果出现前确定；执行清单在经典接入验收后冻结。2026-11-02新主轮已完成，规则未因结果改变，也未按新阈值回头给旧540次结果判通过。** 机器可读规则在[expansion_screen_v1.json](../research/dynamic_benchmark/expansion_screen_v1.json)。

本标准只判断“当前冻结配置是否值得追加实验资源”。绿灯不等于已证明优越、创新充分或达到ESWA投稿条件；红灯只暂停当前配置扩量，不能扩大为四子群研究方向无效。

### A. 先保证对照有效

以下是科学判断的前提，未满足则为“实现/协议待修复”，不得归入算法表现好坏：

1. NSGA-II、SPEA2、离散MOEA/D按原定义检查选择、档案或分解机制；现有同名自定义类不能仅凭类名视为已验收。NSGA-II+普通VNS另标为增强版，保留NSGA-II选择机制，局搜节奏与参数事前登记。
2. 共用动态模型、三目标、四向量语义、合法性处理、增量评价、严格计费及外部结果档案。算法自己的内部选择档案仍依其定义。经典算法不引入我方四子群、QGS、价值学习、家族或共享组合。
3. 检查资源合法性、成功返回解完整重放、固定seed复现、评价预算与限时中断。普通局搜与失败/中断评价均计费；初始化、构造、训练、共享、档案全部计入搜索墙钟。
4. 经典方法先采用有来源的常规配置，每个外部方法最多登记3套小范围配置；开发校准总墙钟最多10分钟。固定使用20_2_3_1、200_8_5_1及两个校准seed。先完成各方法常规配置，额外配置按所有方法的完整均衡轮次运行，不从残缺轮次中挑最好成绩。记录已完成轮次、全部配置及费用；不宣称已穷尽调参。
5. 自有SHARE、VALUE_SHARE、TAIL、SYNC及A0参数沿用已记录版本，本轮不新调块长、调用比例、家族数量、池容量等参数。正式确认时另定公平的完整调参设计，并披露此前开发过程。
6. 新执行清单冻结实际算子、参数、种群/权重数量、数值输入、来源、所有seed、运行顺序及代码版本。旧结果只用于开发背景和费用估算，不与新同时间试验拼接。

### B. 首轮只需270次，而非再跑两套预算

固定主候选为SHARE；VALUE_SHARE作为单独的次候选，不准逐实例挑两者较优者组成“我们算法”。后者若值得保留学习模块，还必须相对SHARE显示实际增量。

采用上一讨论中的8个版本，再加SYNC这个必要消融：

`BASELINE、TAIL、SYNC、SHARE、VALUE_SHARE、NSGA2_4V、SPEA2_4V、MOEAD_4V、NSGA2_VNS_4V`。

|实例|单次搜索T|
|---|---:|
|20_2_3_1|3秒|
|20_8_5_1|4秒|
|100_2_3_1|5秒|
|100_8_3_1|9秒|
|200_5_3_1|12秒|
|200_8_5_1|19秒|

每实例5个新算法seed，合计6×5×9=270次，预计搜索时间5×9×52=2340秒，即39分钟。实例均为开发资料，不称新测试集。

每次只跑一套限时搜索，同时保存0.5T、T和15000成功FE的独立档案快照。因此同时间是主决策，固定FE是解释质量与费用的辅助，不再为它另启一整套JVM。实现双类快照时须检查无未来结果泄漏。

若某方法在T内未达到15000成功FE，标记“预算内未达到”，不补造同FE成绩，不临时降低公共FE点；报告完整配对覆盖率。固定FE结果不能单独触发扩量，也不能因为吞吐低就否定一个同时间质量更好的方法。早期0.5T只作费用和启动诊断，不挑早期最好时点代替末点。

首轮全部270次须完成才作正式分色；只因实现错误、资源异常或总时限停止，不按中途胜负提前结束。独立JVM顺序运行，在实例/seed块内预先打乱方法顺序。搜索计时从algorithm.run前开始，输入读取、JVM启动、配置对象构造和离线QA另外记录。

### C. 指标及“最强经典”提前定义

归一化沿用相同六实例、相同数值输入下原128个独立随机父本的确切最大值，复制数值到新执行清单。**本轮主HV参考点固定为(1.5,1.5,1.5)，敏感性点为1.25和2.0；旧轮1.1主指标保持不动。** 更宽的主点依据旧开发数据已经暴露的盒外点问题事先选定，不能观察新经典排名后再改点。

IGD+统一使用每实例九方法、五seed末期有效档案的非支配并集；规则事前固定，明确是经验参考，不参与任何方法的搜索引导。所有盒外点保留并计数。HV提高2%指该指标在固定尺度及参考点下的相对变化，不是Cmax降低2%或运行速度提高2%。

对方法A、对手B，在每个实例先平均5seed的HV，再计算：

\[
g_i(A,B)=100\left(\frac{\overline{HV}_{i,A}}{\overline{HV}_{i,B}}-1\right).
\]

总体均值、中位数、胜负均以6个实例为单位；五seed不冒充五个独立实例。实质获胜要求g_i≥1%，且该实例至少3/5个配对seed的HV差为正；实质落败对称定义为g_i≤−1%且至少3/5差为负。其余按小差异或波动报告。

上述实质胜/败不同于旧报告中“只要数值正/负就计胜/负”的统计，不得直接套用旧wins字段。判断使用未四舍五入的实际值；恰好±1%的边界按相应seed条件判断，不与小差异区间重复计算。

“最强经典C*”从NSGA-II、SPEA2、MOEA/D、NSGA-II+VNS四个实际方法中选**一个全局方法**：分别计算六实例HV相对A0的比值均值，最大者为C*；并列时取比值中位数更高者，再按方法标签排序。不得逐实例拼接一个虚拟最强算法，也不得临时挑弱对手。四方法完整比较表全部保留；C*来自开发初筛选型，不能把该选择后的差值当无偏正式效应。

如相对HV分母≤1e-12，该比值判为不可识别，不加任意小数制造巨大百分比；先报告原始HV与指标退化问题，不能直接判绿灯。

IGD+防矛盾检查采用有界对称恶化量D_i=200(I_A−I_B)/(I_A+I_B)，两者均0取0；D_i>0表示变差，单位为对称百分比。它不冒称传统的“相对对手百分比”，用于避免接近零的分母失真。

### D. 绿灯：当前配置值得进入扩大确认

须同时满足下列条件。数值是本项目预先选定的实际收益/风险阈值，不是文献公认常数，也不是显著性证明。

|项目|绿灯条件（T末期，主参考点）|
|---|---|
|自身基线的实际改进|相对A0平均g≥+2%，中位数≥+1%，实质获胜≥4/6|
|防单实例撑平均|删去相对A0收益最大的一个实例后，其余五例的平均g仍≥0|
|强普通控制|相对TAIL平均g与中位数均≥−1%|
|外部竞争力|相对C*平均g与中位数均≥−1%，至少4/6实例g≥−1%；允许接近最强经典，不要求小样本全面击败所有对手|
|新组件的必要性|SHARE相对SYNC，或VALUE_SHARE相对SHARE：平均g、中位数均≥+1%，实质获胜≥4/6|
|退化风险|分别相对A0和C*：损失超过5%的实例最多1例，超过10%的实例为0例|
|辅助指标|分别相对A0和C*：IGD+对称恶化中位数≤5%，且D_i>5%的实例不超过3例|
|参考点稳健性|在1.25和2.0各点：相对A0的平均及中位g均≥0；相对同一个C*均≥−2%；不重新选择C*|

六实例不设置p<.05硬门槛。报告原始差值、分布、均值、中位数、探索性区间和最差实例；不能把“未显著”写成无效。绿灯只表示投入下一批独立确认值得，不代表已证明泛化。

若SHARE绿灯而VALUE_SHARE未通过其相对SHARE的增量条件，只扩大SHARE，学习组合保留原始结果和消融身份。若二者都绿灯，分别报告，不能汇总成一个事后最优方法。

### E. 红灯与黄灯

实现和计时有效后，以下任一情形足以给当前配置红灯，暂停大规模扩量：

- 相对C*的平均g和中位数均≤−5%，且实质落败≥4/6。
- 相对A0或TAIL任一方法，平均g≤−3%、中位数≤−1%，且实质落败≥4/6。
- 相对C*有至少2/6实例损失超过10%。

不满足红灯、又未满足全部绿灯条件的，记黄灯。典型情况包括小幅正收益但实例方向分散、同FE较好但限时不足、末期追赶、辅助指标矛盾或参考点改变判断。**黄灯不直接扩大，不因它追加无上限调参。**

### F. 最多一次有界复核，随后结束初筛

只在没有红灯/实现错误，首轮组件必要性和相对TAIL的条件已经满足，且有可量化的费用或启动期疑点时允许复核：固定15000 FE对C*的中位HV收益≥2%且至少有4个完整实例配对（每例双方5seed均达到该FE点），或median_i[g_i(T)−g_i(0.5T)]≥2个百分点。不能用延时绕过一个尚无必要性的模块或已有更强普通控制的问题。

优先复核黄灯SHARE；仅当SHARE绿灯、VALUE_SHARE黄灯时才考虑后者。全轮最多选一个候选，不能每个黄灯都延长。

复核仅跑锁定候选、A0、首轮锁定的C*，六实例、3个新seed、统一2T：共54次，预计搜索936秒，即15.6分钟。保持实例、参数、模型、参考点不变；IGD+沿用首轮冻结的经验参考。只分析新3seed在2T的末点，不和首轮5seed在T的末点混合。每实例实质胜要求改为至少2/3seed方向一致。

只有相对A0平均≥2%、中位≥1%、实质胜≥4/6，相对锁定C*平均及中位≥−1%，退化/IGD+/参考点保护仍满足，并且首轮已满足对应组件必要性时，才允许“有限扩量继续”。该结论只说明较长预算下相对锁定锚点有潜力，**没有测试其他经典算法在2T的表现**；正式扩大时仍须保留全部经典对照。复核不明或仍未满足则暂停当前配置扩量，不开第二轮延时或改参追结果。

### G. 时间上限、交付与未完成状态

主轮39分钟搜索＋最多10分钟经典配置校准＋一次15.6分钟复核，搜索/校准合计约64.6分钟，额外预留进程启动、输入准备、快照、离线QA和分析时间。**整个性能初筛墙钟硬上限90分钟。** 此上限不包含首次经典算法接入开发与必要工程验收；不能以赶90分钟为由省略正确性检查，也不能把首次开发承诺成40分钟完成。

若预估或实际资源不足，启动新单元前检查总预算；不足以完成预定单元则停止并报告“证据不足”。270次主轮未完成不得基于子集判绿/红；不暗中延长预算、替换seed、删去退化实例或抹去失败。

最终只交一份决策表：候选、C*、六实例原始差及seed方向、均值/中位/去最佳实例结果、最差损失、IGD+、参考点敏感性、实际FE与全部时间、每项标准满足与否、绿/黄/红或证据不足及理由。既有540次开发结果单列引用。

公平比较与事先约定协议的一般依据见[Beiranvand等的比较规范综述](https://doi.org/10.1007/s11081-017-9366-1)；同一条运行轨迹记录预算和达标信息的思路参照[COCO性能评价](https://arxiv.org/abs/1605.03560)。本节2%、1%、5%、10%及90分钟均是本项目的资源决策选择，不声称上述论文给出了这些数值，也不把连续黑盒测试问题直接替代本调度模型。
