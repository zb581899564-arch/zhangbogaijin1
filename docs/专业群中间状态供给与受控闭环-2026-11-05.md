# 专业群中间状态供给与受控闭环

2026-11-05。**专业目标允许经过的中间状态已有可追溯作用，短程闭环在四个“实例×模型”组合中有三个呈现联合正方向；跨职责传递的独立因果收益仍未隔离。** 这为保留四职责提供了具体依据，不证明最终算法已胜强经典，不恢复旧学习或普通基座资格判定。

本轮先完成两个零FE审计，再事前冻结一个只改变接受约束的闭环对照。原四职责/QGS/固定FA家族/条件共享默认主线未改。当前PA仍是没有原QGS/条件共享的普通隔离适配，不能冒称最终四子群创新算法。

终点按记录中的首次已付费`bornFE`分组。初始化前100点单列INITIAL；之后每个槽完整访问2N−1集合，按15M/55CENTER/15E/15W的固定槽序推算调用职责。该公式在已有两条工程轨迹的47600个真实混合步上逐项核对一致，并检查了角色交界、首末FE及部分代费用。

500k时PA_JOINT的CENTER首次产出占比为：20例283/318、294/334；100例1758/1969、1578/1787，约88%–90%。这只是首次调用方，不代表其他职责没有提供祖先或供体。

两条工程轨迹分别有4990/25301次跨职责读取，其中309/2480次同时被接收并改变物理排程。只把读取、实际改变和新ND准入分开计数，不把流量当性能增量。对终点删去某职责点集后，已补HV、固定经验参考IGD+及相对全部强对照的双向C；这是同一结果的回顾性删点，不是算法消融，损失也不能直接相加分摊贡献。

## 3. 新的受控闭环到底改了什么

[冻结协议](../runs/pa-specialist-bridge-probe-20261105-212900-801483/protocol.json)登记新seed14030003/14030037，仍是20_8_5_1、100_2_3_1两个既有开发实例。

- FREE保持原普通PA接受规则。
- BLOCKED只给三个专业职责增加一条约束：即使自身目标改善，也必须满足CENTER当时的原接受规则；CENTER自己不变。
- 模型分别使用原JOINT和原RELABEL，两者都完整执行，不事后选较好的模型；四职责标签、初始100解、表示、模型/子集流程、供体抽取、费用和解码不变。闭环产生的后续候选可以不同，相同seed不意味着候选逐个相同。
- 保留NSGA2_DEEP、FULL_SHARED_DEEP、LI_RECON_DEEP三个原增强对照，原共享和Li是规范重建版本，不是作者发表成绩。

每条运行两个完整PA代：20例7900FE，100例39900FE。这个长度事前按“后访问的ENERGY/WORKER_COST至少有机会在下一代给CENTER供体”确定，各对照同实例支付相同FE。不是只选一个看起来领先的时点，也不是500k或同时间优势检验。

只有隔离副本中的PaPopulation/PaCapabilitySearch被编译覆盖，默认源码未改；共享Python入口仅增加可选VM设置参数，默认行为保持。新JVM的干预开关显式记录，关闭时两条已知付费序列SHA及最终前沿与冻结接口版完全一致，116/934个待干预状态计数也与独立审计相符；开启时实际发生180/1722次阻断，初始化相同、预算和完整代成立。工程通过后才启动28条科学轨迹。

## 6. 现在能推进什么，不能推出什么

可以保留一个更具体的工作假设：**专业群除了贡献当前精英，还允许搜索经过CENTER当时不接受的中间排程；完整混合能够把其中一部分状态带到其他职责。** 两种模型都能出现该现象，因此不能把它归功于尚未立住的学习树标签。不能据终点大多由CENTER产生就把专业群取消。

但当前闭环干预同时改变专业群自身续搜和后续供体，所以隔离的是“专业接受自由度”的总效应；它没有单独证明跨职责通信优于专业群自己的继续搜索。下一项应保持工作轨迹的接受规则，单独干预这类状态对其他职责的可见性，才能回答通信的独立作用，不能直接加一个中间状态共享器宣称有效。

另一个只读发现见[visibility.json](../runs/pa-specialist-bridge-review-20261105-213529-864323/visibility.json)：116/934个专业特有接受状态中，只有24/27个曾作为跨职责供体；92/907个没有被其他职责直接读取，也没进入下一次模型样本。它们仍参与本槽自身续搜，不能称为浪费或已有可回收收益；尚不知道未读状态是否更有价值。当前单槽完整程序会覆盖许多中间状态，这是新普通基座中的可核查传递边界，不是对原共享实现的错误指控。

尤其已经核对原CooperationSupport：它对所有已付费评价采集工厂记录，再按固定家族/工件集进行本厂非支配与容量截断；**原共享没有按全局ND过滤所有专业中间状态。** 所以不能把新方向写成“修复原池漏记全部被支配状态”。若后续研究中间状态，必须区分完整基因供体、工厂记录、跨职责可见性和保存后的实际成本/独立价值，不重复过去全付费ND教师或池容量调参的失败。

后续顺序：先隔离直接跨职责可见性与自身续搜；必要时再验证未传递状态是否有超过当前供体和无角色状态的可用价值；有实际独立收益后才设计与原QGS/条件共享的整合，另行解决现普通基座的初始资源元组封闭限制。最后仍须长预算、同时间、多实例新seed及强经典/Li/原共享独立确认。以上均尚未完成，Goal保持active，原学习和统一资格停止决定不变，不调接受阈值或把FREE/BLOCKED按实例拼接。
