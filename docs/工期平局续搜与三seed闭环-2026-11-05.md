# 工期平局：物理平台存在，两个具体续搜规则未通过

本轮保留四目标职责、QGS、原FA家族和条件共享，只在隔离环境观察或改变局搜的工期平局判定。默认主线未变。工期最大值会掩盖其他工厂的改善，但FACTORY_LEX的配对续搜和普通COST_LEX的新三seed闭环分别未通过各自冻结门槛，没有形成合格完整算法。

## 可复核证据

- [CENTER只读审计](../runs/acceptance-plateau-audit-20261105-024122-953625/)：两例OFF/ON各50万FE，共200万重放FE。被拒绝非支配平局占目标变化比较的6.957%/22.294%，前一例未达到20%；不实现CENTER新接受规则。
- [工期平台只读审计](../runs/makespan-plateau-audit-20261105-024442-974819/)：两例各50万FE，共100万重放FE。Cmax相等且各厂工期逐分量不差、至少一厂更好的比较占18.510%/17.074%，两例达到事前机制门槛。全部重放的付费序列摘要、末档、FE前沿、初始化、物理账本及计数等价；返回QA分别1526和763次。
- [有限续搜](../runs/makespan-continuation-probe-20261105-024837-581604/)：两例、每例两个已付费source cohort各8个M自由父本、两个新续搜rep、三规则，共192条×515FE=98,880成功FE。每条父本重放1FE，跨厂2FE，八个相同工厂槽各64FE。返回及保留点完整QA3188次，工程另50万FE。FACTORY_LEX相对COST_LEX的逐父本工期胜数为8/16、15/16，前一例低于事前9/16；停止该规则。

FACTORY_LEX仅在精确Cmax平局时按降序各厂完工向量比较。普通COST_LEX则按TEC、TWC破平局，在小续搜中有更高条件新增HV。因此另立新seed协议验证这个普通控制，原FACTORY_LEX失败不变。

## 小续搜为何不足以触发扩量

[零新增FE阶段解释](../runs/makespan-tie-screen-20261105-025223-471920/stage-explanation.json)确认三种FULL规则的初始化及5100FE前沿相同；按源码，该新判定直到局搜才调用。COST_FULL对STRICT_FULL在100工件例的中位HV依次为：15,000FE +9.093%、50,000FE +9.249%、100,000FE +2.206%、250,000FE +1.534%、500,000FE −0.321%。20工件例15,000FE +0.602%，50,000FE已约−0.002%，最终−0.815%。早期改善和最终预算改进确实是不同问题。

这些只是保存的公共检查点：50,000仍在第一轮M局搜，100,000/250,000在CENTER局搜，500,000在第二轮M局搜。没有精确M/C阶段边界快照，不补造边界收益。尤其，首轮M局搜不会直接替换CENTER入口粒子或其已冻结参考集，CENTER局搜也不直接消费共享池；M决策会改变后续随机流和池/外档状态。不能把后段差异直接解释成“CENTER抵消了专业群贡献”或“共享池导致退化”。这需要独立通道诊断。

## 工程与创新边界

原STRICT通过完整50万FE付费序列及冻结结果等价。24项实际内核零解码判定检查通过，涵盖主工期改善/恶化、精确平局、Pareto与成本控制差异、其他角色不变。补充夹具前两次遗漏IOException声明和RNG重置，均零评价退出，原日志保留；修正仅针对夹具，未改运行中的冻结类。

[已有字典序工期工作](https://arxiv.org/abs/2212.09077)与[字典序排程/重排研究](https://arxiv.org/abs/1805.03437)说明该类排序思想已有先例。本轮没有证明疲劳特有价值、四子群协作新颖性、真正TIME_LIMIT优势或独立实例泛化，也不声称复现李明哲原作者成绩。

下一项先审计**代末全局结果＋局搜出口的200→100保留**，与已测试的QGS每批组内生存分开：源码此处使用共同PDDR、固定家族配额和平局的稳定顺序，真实加载身份仍待核对。先核对真实类，再只读记录当前FULL的完整代末池、去留、目标重复与角色来源；离线比较同配额保留能否增加真实覆盖，不能直接新增选择器或更换算子重跑。如果没有实质可达的保留损失，就停止该假设。goal保持active，尚未达到最终目标。
