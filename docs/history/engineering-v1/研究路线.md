# 研究路线

目标：以 ESWA 等期刊为投稿目标，形成由问题结构、算法机制和可靠对照共同支撑的独立贡献。当前阶段为基线核查，未确定最终创新点，也没有实验优势结论。

## 1. 先建立可信基线

优先解决 `代码核查与修复记录.md` 的 S01–S04：三目标接口、严格 FE、统一随机源、第四章模型版本。随后用论文小例导出工序时间轴和逐项目标分解，手算核验资源可行性。

保留三个不同身份：原始交付代码、当前工程修复版、经模型核验的论文规范基线。旧代码中的 bug 修复应作为复现贡献说明，不能混入新方法的性能提升。

建议先以第四章问题作为主研究平台，第三章用于模型简化后的迁移或适用性验证；两者具体目标语义和资源约束分别冻结，不能把两个问题的指标放在同一张排名表。

## 2. 候选机制，待验证后定题

优先考察“资源瓶颈感知、按实际计算预算分配的搜索”：用当前调度的关键工厂、机器等待、工人 setup 等待等可解释状态，决定搜索哪个向量、哪个工厂或哪类邻域；按真实 FE 或时间计费，衡量每单位预算的非支配改进。

它针对当前代码已暴露的局部搜索开销和人工固定循环次数，提出可被反驳的假设：相同预算下，将有限评价分配给当前瓶颈是否能提高 Pareto 前沿质量。候选机制需要与固定分配、随机选择、原 Q-learning 选择和简单自适应控制比较，避免只证明优于弱控制。

另一条候选是扩展后续阶段调度决策的可达域。该方向必须先分析表示能覆盖什么调度、是否改变原问题、额外自由度带来的成本，以及相同预算下搜索是否受益。不能由某个微例或可达非支配点直接推断大规模性能优势。

暂不同时引入疲劳新目标、动态扰动、深度 RL、更多编码向量等多重变化。上述主题在原论文本身的展望和相关文献中已有讨论，选题前需检索其具体已有工作。当前没有完成新颖性检索，不给候选冠以“首次提出”。

## 3. 进入正式实验的条件

1. 规范基线及共享解码经手算小例和约束检查通过。
2. 新机制职责独立，参数、适用阶段、费用和失败行为可说明。
3. 开发实例与最终测试实例分开；冻结实例、seeds、预算、指标与统计方案。
4. 先做最小机制诊断；若稳定退化，保留失败证据并回到机制解释，不以反复筛 seed 替代论证。
5. 再运行多实例、多 seed 对照、消融、规模与成本分析。

## 4. 文章应回答的问题

- 原方法在哪类资源结构或预算条件下出现可复现的不足？
- 新机制为何针对这一不足，其作用如何与编码、解码和额外计算量区分？
- 与规范李明哲基线及经典/相关近期方法相比，在等 FE、等时间条件下何时有效、何时失效？
- 新机制的消融、参数敏感性、规模泛化和实际调度含义能否支撑结论？

ESWA 出版方强调方法贡献应清晰，反对用改名或隐喻包装已有优化概念；应使用标准术语解释针对问题的适配和实质增量。[出版方说明](https://shop.elsevier.com/journals/expert-systems-with-applications/0957-4174)（2026-10-31 核对）。期刊目标是研究标准与方向，不能据此预先保证录用。
