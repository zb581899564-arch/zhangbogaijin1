# v8：普通跨厂交换、资源重绑定与疲劳信息增量

本轮已按冻结协议完成。**交换加重绑定能提高部分协调障碍附近的小预算搜索效率，但覆盖有限，不能替代普通复合；疲劳边界相对时间边界仍未建立独立收益。** 共享解码器、原材料和Java整套算法保持不变。

证据：[冻结协议](普通跨厂交换与重绑定协议-v8.md)、[完整主单元表](../runs/fatigue-exchange-v8-20261031-230127-858222/report.md)、[全部模式/解释组/确认组汇总](../runs/fatigue-exchange-v8-20261031-230127-858222/summary.json)、[预算与同池审计](../runs/fatigue-exchange-v8-20261031-230127-858222/audit.json)。

## 设计与可归因范围

8个v7实例作为解释组，另加4个预定新N=4合成实例作为确认组；beta0、强疲劳快恢复、强疲劳慢恢复调用同一解码器。原230400行目标表按源码及输入一致性核对后复用，新实例三模式另作221184次全空间普查。不是作者benchmark，不涉及新增休息、后阶段基因或模型目标。

四种普通候选分别是：两个不同工件的两次强N1复合；仅两工件资源重绑定；跨厂工件交换准确队列位置并保留各自资源id；交换位置再给两个工件重选首阶段工机资源。最后三者都保持各厂工件数量；仅重绑定还保持厂别和顺序。重绑定的15个资源组合包含只改变其中一个工件的情况，部分终点不在“两个不同job都实际改变”的N2内；计算N2覆盖比例时明确取交集，不能以此夸大覆盖。

另设相同8个交换重绑定候选池，分别随机、廉价缺陷、时间边界、疲劳边界选择一个子本完整评价。后两者调用既有同一真实首阶段重算引擎，仅反向疲劳信息开关不同；没有为跨厂迁移偷用FA固定增量缓存。父本trace、评分、首阶段部分调用和缓存失效费用全部支付。真正同池快照在固定父本上独立评价全部8候选，不反馈在线搜索。

每实例两个匹配父本：从三模式严格障碍并集抽一个，再从全空间抽一个；各模式共用，障碍并集层不保证在每个模式都严格。本轮新seed强快模式的4个并集层父本中，只有2个在该模式确为严格障碍。因此以下搜索分层不能解读为4个全是强快局部最优；完整覆盖表则遍历该模式全部65个真正严格父本。

每父本3个搜索seed、8方法，分别33次完整评价、20ms、80ms：共5184次独立局部链。完整FE包含1父本+32子本；部分重算单列。内存决策记录计时，磁盘序列化、普查、快照和最终QA在实验总成本中单列。超时子本付费但不接收。

## 1. 覆盖提高抽中概率，但仍会漏掉改善

确认组全部严格障碍的覆盖：

|模式|普通复合|只重绑定|只交换|交换＋重绑定|
|---|---|---|---|---|
|beta0|22/22|1/22|9/22|19/22|
|强快|65/65|29/65|21/65|53/65|
|强慢|58/58|33/58|20/58|51/58|

分母是各模式4实例严格父本总数，分子表示至少一个候选能改善。普通复合覆盖全部是N2障碍定义的结果，不是独立优势证据；需要继续看概率与费用。

强快组中，交换重绑定只覆盖普通N2改善终点的平均35.26%，但精确16次抽样成功概率均值65.30%，高于普通复合19.34%。它通过缩小且偏向有用结构的池提高抽中概率，并没有覆盖更多不同改善终点。只交换为32.25%，只重绑定12.17%，普通两者联合的重要性有实测支持，但不是新颖性结论。

事后只读检查显示，交换重绑定和纯重绑定的并集仍漏掉7/65个严格父本；其中2个的全部N2改善必须改变逐厂工件数量，另5个有保持数量的改善，却仍不在所测两类候选内。保持数量不是唯一缺口，厂内顺序/更一般复合结构也不可省略。

## 2. 相同完整评价次数与真实时间给出分层结论

确认组强快TEC相对初始父本的平均改善百分数：

|预算|并集层：普通复合|并集层：交换重绑定|均匀层：普通复合|均匀层：交换重绑定|
|---|---|---|---|---|
|33FE|0.2014%|0.5347%|21.3964%|15.6546%|
|20ms|0.3332%|0.6796%|22.9260%|17.4808%|
|80ms|0.7769%|0.7747%|24.8881%|18.1288%|

先平均父本3seed，再按实例配对。在并集层，33FE和20ms是3胜1平，80ms为2胜1平1负，平均差接近0；均匀层三个预算都为0胜4负。不能只展示小预算障碍层的正结果。

33FE并集层交换重绑定平均耗时6.296ms，普通复合8.327ms；20ms下分别约106.17/79.75次完整调用。候选生成更便宜与抽样更集中共同起作用，不能把这些收益归给疲劳信息。

更长预算不能弥补可达范围：均匀层4个新实例中，3个的固定逐厂数量全空间最优TEC严格差于允许负载数量变化的全局最优。例如seed271003父本为2+2分配，所有保持数量的方法即使搜到最优也只能改善16.365%，允许数量变化的上限为27.917%。这些是事后全空间界，不是在线免费oracle或任何方法已达到该界的主张。

## 3. 疲劳信息仍未优于同池时间边界

确认主单元强快模式，把两父本层在实例内等权平均后的配对结果：

|预算|疲劳−时间：平均改善百分点|4实例胜/平/负|
|---|---|---|
|33FE|-0.0458|1/1/2|
|20ms|-0.0458|1/1/2|
|80ms|-0.1705|0/2/2|

疲劳对随机池有正的均值差（33FE/20ms/80ms分别+0.8278/+0.2176/+0.2110个百分点），对廉价评分也有均值差；但时间边界是必须保留的更强对照。因此不能把“胜随机”称为疲劳信息的独立贡献。

真正相同8候选的快照也未支持更准：强快均匀层时间边界选中改善均值12.3525%，疲劳11.9236%；oracle regret分别1.6952/2.1241个百分点。并集层三种评分同为0.0875%，regret为0。故问题不只是额外耗时，本批同池排名也没有疲劳优势。

强慢模式有一个实例驱动的补充正信号：33FE和20ms疲劳对时间均值+0.1220个百分点，1胜3平；80ms变为-0.0024，0胜3平1负。解释组N=4强快三个预算疲劳对时间均为负；N=3相同。全部结果保留，不因该补充正信号改变主单元或挑预算。beta0固定FE的72对轨迹完全一致，证明信息开关控制实现正确；时间限额下允许因实际速度不同而出现轨迹差异。

## 研究取舍

保留普通复合作为覆盖广的强对照，交换重绑定可作为协调障碍附近的补充候选。不能用交换重绑定替换一般负载/顺序搜索，不能把纯重绑定收益、候选缩池和实现便宜归为疲劳反向的贡献。

当前不将疲劳边界升级为算法核心：它未胜同池时间边界，4个确认实例也不足以证明普适同时间优势。若继续研究，应先明确普通邻域各自保持了哪些不变量、缺失哪些改善，而不是再堆评分模块。是否设计覆盖互补的组合机制，应另立可被否证的假设与协议；本轮没有实现组合控制或改整套算法，也没有完成新颖性全文查新。
