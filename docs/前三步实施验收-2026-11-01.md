# 前三步实施与必要验收

日期：2026-11-01。结论：动态模型、完整动态四子群基线、有限块联合生成器及四种选择控制已实现，并完成下列正确性与联调验证。未进行第四步的300次算法性能初筛，未得到同时间HV/IGD+优势结论。

## 1. 交付

### 第一步：共同模型

新增[动态模型合同](动态模型合同-v1.md)及独立Dynamic系列模块。实现开始疲劳修正工时、指数积累/恢复、工作期暴露的稳定积分、确定性追加式全解码和独立时间轴验证。设置和加工按同一疲劳系数缩放，完整工时占用机器与工人。主目标仍是Cmax/TEC/TWC。

完整保留原静态Decoder和原静态模型合同；新模型关闭插空/右移。β=0对应同一追加解码规则下的无工时疲劳反馈，不冒称原静态调度规则完全复现。

### 第二步：完整动态基线A0-D

新增DynamicEvaluation适配，接入原CanonicalHmopso全流程：初始化、四群、原Qg、个人历史、代边界引导档案、全局更新、工厂间/工厂内局部搜索和环境选择。

精确重算支持改变per-job FA，复用整厂未变结果与严格相同首阶段前缀；变化工厂后阶段完整重算。缓存核对编码、实例数值与来源、疲劳参数及模型版本。构造器已实际推进的前缀直接用于正式评价，避免重复模拟。

RunContext新增可选协作式时间截止。预算中断只返回完整评价的独立档案，评价中断计入failed并另记timeInterruptedAttempts。达到截止点时的原子档案操作可能产生超时尾段，公开实际searchSeconds和deadlineOvershootSeconds。

### 第三步：联合生成器

新增src/algorithms/joint的独立模块，提供RANDOM/GREEDY/TAIL/VALUE。默认b=4、c≤6、rho=.25、epsilon=.1、20个物理摘要特征；三个边界方向和综合方向各有一个线性余程模型。

候选包含可完成见证、父本/pbest/gbest信息及两次合法探索。只推进候选一步，实际提交一个动作，保持块外编码；最终编码不需要额外修复。模型参数在当前方向的全局批次内冻结。

训练口径具体化为：同一方向、同一模型版本下，连续收集至少64条真实完整子代轨迹，在完整全局批次结束后拟合一次岭回归，然后释放该批群。后续重复同样过程，不以单工件状态数代替独立轨迹数。每条子代的训练权重总和为1，正则系数.001且截距不正则；启动期使用TAIL。

所有算法专属特征预计算在搜索计时中执行并记录featurePrecomputeNanos。无诊断采集时RANDOM/GREEDY跳过其不使用的尾程特征预计算和提取，避免给简单对照添加无关成本。

TAIL规则已固定：剩余首阶段时间按补全见证的资源与当前可用/疲劳状态逐工件独立估计，忽略未来工件之间的竞争；剩余首阶段能耗、工资分别取该厂合法资源上的最小基础费用；后阶段对各工件按其工厂累加各阶段最小基础时间/能耗/工资。三个最小值可来自不同资源，因此整体仅是廉价启发估计，不保证为联合可行补全，也不当作真实目标或严格下界。

## 3. 有界机制诊断及费用

默认VALUE最终验收目录的`value/mechanism-diagnostic.json`保存4条启动期轨迹、16个决策、58次额外完整重算；另有trajectories.jsonl记录候选、评分、选择和补全见证。

真实候选代价按“相同已提交前缀＋当前候选＋其兼容见证＋固定块外后缀”重算，逐决策记录regret。该固定见证续接与学习器未来继续选择的策略不同，不能将其称为最优余程或on-policy预测精度。当前4条是冷启动样本，仅验证可追溯诊断链路；不用于科学性能结论。

全部额外重算在搜索停止后执行，费用记录为offlineSeconds/fullDecodes，不反馈动作、训练或档案。正常入口默认traceLimit=0，关闭该诊断。

## 4. 可运行入口

在项目目录使用既有Python：

```powershell
E:\conda\python.exe scripts/run_dynamic.py --mode BASELINE --fe 15000
E:\conda\python.exe scripts/run_dynamic.py --mode VALUE --fe 15000
E:\conda\python.exe scripts/run_dynamic.py --mode VALUE --fe 1000000 --seconds 10
E:\conda\python.exe scripts/verify_dynamic.py
```

mode可选BASELINE/RANDOM/GREEDY/TAIL/VALUE，默认strong_fast合成情景；profile另支持weak/strong_slow/beta0。输出独立目录含实际设置时间、逐工人参数、配置、三个目标前沿、四向量、动态时间轴、阶段/模型/费用统计及离线QA次数。

`--full`关闭普通父本缓存重用；生成器已推进前缀仍作为准确构造结果传给评价，不无故重做。`--small-search`明确标记诊断配置，不能冒称原默认。`--skip-build`仅在兼容依赖已有构建时使用；动态自有源码仍编译。`--trace-limit N`开启付费有界离线诊断，默认关闭。

## 5. 已修复及未包含事项

本次开发过程的失败日志全部保留：初次接口使用了旧PermutationSolution未公开的机器向量getter；一次并行接口对齐编译误用了无资源下标的mu/beta；第一次输出试图直接排序不可变档案。分别改为既有机器属性访问、资源索引API和输出副本排序后，上述检查通过。另将算法专属特征预计算移回计时范围，并消除简单控制不使用的预计算成本。

当前没有增强FA家族/整厂池组合、新群级信用学习、新局部块修复，也没有第四步的300次固定协议性能初筛。全部36实例仍是开发资料。后续应冻结第四步实例、预算、seed和指标后再比较，不从本次单seed联调的前沿大小或耗时判断优势。
