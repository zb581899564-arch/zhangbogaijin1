# 动态疲劳成本与复用 v3：真实首阶段提升单步质量，完整疲劳反向尚无稳定增量

本轮已完成独立局部链验证。**计入全部在线搜索耗时后，真实首阶段+疲劳边界法在预先指定条件下优于随机，但没有证明优于共享真实首阶段的时间通道或廉价时间通道。** 缓存能节省实际计算，真实复用次数却明显低于前轮q=4/16情景，且首阶段重算本身仍是主要成本。当前不将该方案接入整套Java算法。

## 固定设计与执行证据

按[运行前协议](动态疲劳成本与复用协议-v3.md)，沿用6个合格实例和原重建数据/合成疲劳参数；新父本seeds为17、41、83、173、347。90个实例/父本/疲劳场景，TEC和均衡方向，固定24次子本评价与0.25秒两类预算，四种主方法，共1440条主链；另有30条每步强制重建消融，共1470条。

预先指定主要单元是强疲劳快恢复、TEC、0.25秒，两个主要对照为time_only与随机。均衡方向和其他疲劳场景全部保留。目标尺度固定为初始父本目标，实际严格改善才接受；接受即缓存失效，拒绝才复用。超时子本的改善不进入限时结果，超时尾部费用进入实测收益率。

代码位于 `research/fatigue_reuse/`，未修改v1/v2物理代码或Java模型/优化器。候选仍与v2合法局部规则逐项相同，只对入池16个描述创建编码。数值首阶段共用同一物理递推，省去评分不需要的逐工序日志；初始90池、1440候选的C/v/费用全部与旧日志版一致。

8项新检查通过，覆盖候选流一致、数值首阶段与完整解码一致、固定归一化与旧边界公式一致、过期缓存拒用、复用/重建轨迹一致、拒绝复用、截止后改善排除、轨迹审查及配对统计单位。全部70578步逻辑/候选/缓存/截止审查通过，1470个最终调度额外完整解码并验证约束/疲劳/目标。30对消融的选择、分数、接受及最终轨迹完全相同。

原始记录：[本轮目录](../runs/fatigue-reuse-v3-20261031-172612-730865/)、[机器汇总](../runs/fatigue-reuse-v3-20261031-172612-730865/summary.json)、[全部单元表](../runs/fatigue-reuse-v3-20261031-172612-730865/report.md)、[审查](../runs/fatigue-reuse-v3-20261031-172612-730865/audit.json)。

## 主要结果：能胜随机，尚不能胜时间通道

以下是强疲劳快恢复、TEC、相同0.25秒预算的30条配对主链。收益为相对于同一个初始父本的归一化真实目标下降；完整耗时包含一次未能在截止前完成的非抢占尾部，尾部改善不计收益。

|方法|最终平均收益|完整实际耗时|准时完成决策数|
|---|---:|---:|---:|
|真实首阶段+完整疲劳边界（cut_fatigue）|13.475%|253.40ms|41.53|
|真实首阶段+时间边界（cut_time）|13.400%|252.62ms|42.67|
|旧状态廉价时间通道（local_time）|13.378%|252.40ms|66.00|
|相同合法局部池内随机|11.967%|251.06ms|136.37|

完整疲劳边界法的配对收益差，按实例→父本seed分层bootstrap2000次，描述性95%区间：

|对照|平均差，百分点|区间，百分点|
|---|---:|---:|
|共享真实首阶段的时间边界|+0.0755|[-0.2339,+0.3892]|
|廉价时间通道|+0.0973|[-0.7011,+0.7860]|
|随机|+1.5082|[+0.3269,+2.6705]|

以实际含尾部耗时为分母的收益/秒比较也相同：对两种时间控制的区间跨0，对随机的主要单元区间为正。因此有证据支持这个组合的引导比随机更有效，**不能把它归为完整疲劳反向的独立贡献**。

在全部场景/方向的固定时间与固定评价次数对照中，完整疲劳法相对共享真实首阶段时间边界的收益差区间，没有一个完全高于0。均衡方向相对随机的限时差区间也都跨0，不将TEC结果推广为三目标总体优势。

|真实首阶段+完整疲劳边界|12.870%|193.12ms|

|廉价时间通道|10.922%|123.67ms|

真实首阶段方案有同FE质量收益，完整疲劳法相对廉价时间通道高1.948个百分点，区间[+1.028,+2.908]；但耗时增加，廉价方法能在相同时间尝试更多候选。转为0.25秒后，两者差缩为0.097个百分点且区间跨0。不能以同FE提升替代同时间提升。

|组件|平均时间|
|---|---:|
|16候选数值首阶段重算|3.268ms|
|相同16候选旧逐工序日志版|7.957ms|
|单次minimal完整解码|0.936ms|
|单次trace完整解码|1.796ms|

当前内核为每候选完整重算首阶段；尚未测试只重算受影响工厂、复用未变前缀等增量方案。本轮费用判断仅针对当前公开实现，不能推出任何可能的准确首阶段实现都不值得。

## 实际伴随能复用几次

q包含首次使用，q-1才是后续重复命中。主要单元完整疲劳法，30条链共597个缓存周期、1276个真实评分池：

|实际缓存统计|结果|
|---|---:|
|全部周期平均q|2.137|
|q中位数|1|
|q的90%分位|3|
|q>=4的周期比例|9.38%|
|接受新父本终止的周期数|567|
|上述已接受终止周期平均q|1.806|
|上述周期q>=4比例|7.94%|
|预算结束右删失周期数|30|
|右删失周期已观察q均值|8.40|

1276包含30个最后未准时完成的尝试；仅按准时完成池/全部构建次数计算约2.087。右删失周期多发生在父本不再改善时，其较高q会抬高总体平均；不能据此认定每次有效改进都能摊薄4次或16次。共享真实首阶段时间边界的全部周期平均q为2.230，廉价时间通道为3.418，后者在相同时间能尝试更多池。

30对强疲劳快恢复/TEC/固定24步的缓存与强制重建消融中，轨迹全部一致。缓存平均构建17.43次而非24次，平均少建6.57次；合并epoch的q为1.377（逐链q的算术平均为1.595，口径不同）。每步重建/缓存总耗时比的中位数为 **1.049**，平均节省14.01ms，30对中29对缓存更快。

缓存确实有实际价值，幅度约为这个短链总费用的几个百分点；它没有抵消每个池都要发生的首阶段重算成本。此前q>=4/16的成本情景不能直接用于实际接受驱动的搜索。

## 研究判断

目前可以保留三条有证据的结论：准确首阶段提高同FE选择质量；接受驱动的缓存复用通常有限；完整疲劳后阶段反向相对时间通道的增量仍未证明。廉价时间通道在主要限时单元已接近完整方案，不宜为当前这点未确认增量改整套算法。

如果继续，应优先在新冻结协议中检验受影响工厂/前缀的准确增量重算，并保持共享首阶段的时间通道和廉价时间通道两个控制；不通过假定高复用、添加第二套Q-learning或只挑正场景来扩大结论。当前三目标分布式多目标优化器、HV/IGD+、真实人体校准和发表级总体优势均未验证。
