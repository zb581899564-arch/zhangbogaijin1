# 动态疲劳机制验证协议 v1

本次只验证共同解码器、反向传播和候选预测，不接入 Java A0、不增加 Q-learning、不运行整套 MOPSO。完成标准是物理/导数检查、同池公平比较和可追溯成本；是否优于控制由结果决定。

## 运行前冻结

固定设计见 `research/fatigue_mechanism/protocol.py`；每次运行先创建独立目录，写 `protocol.json` 并复制 Python 源码，之后才读取实例、生成候选和评价。失败写 `failure.json`，不覆写旧目录。不因结果退化调整参数、seed、候选数或选择规则。

- 实例：`20_2_3_1`、`20_5_3_1`、`20_8_3_1`、`50_2_4_1`、`50_5_3_1`、`100_2_3_1`，均须在36个式(8)合格清单内。
- 每实例父本 seeds：7、19、43、101、271。随机合法父本，各厂至少一工件，工厂分配固定。
- 每父本16个不重复合法候选；同厂两工件的 WA 交换、MA+WA交换、顺序交换、插入及联合交换。纯 JS 编辑使资源属性随工件移动。候选生成不读取目标值。三档疲劳复用同一父本和候选池。
- 每候选至多16个直接改变的首阶段局部模块，包含直接重连的资源后继；超出就报错，不按真值过滤。准备局部模块仍需扫描首阶段编码，该成本计时。
- SUT 用 numpy PCG64 离散 U[1,9]，seed=314159+实例序号；standby=1。均明确是重建数据，不是作者原参数，也不与旧 Java 随机生成器声称逐值相同。
- 三档合成疲劳：weak `(beta=.1, alpha*t=.10, mu*t=.8)`，strong_slow_recovery `(.7,.45,.08)`，strong_fast_recovery `(.7,.45,.8)`。`t` 为名义工时中位尺度；每工人各参数独立乘 U[.85,1.15]，h0=0，异质性 seed=271828+实例序号。场景用于结构敏感性，不是实测生理参数。

共6×5×3=90个父本/场景，16×90=1440次候选事后真值。不能将四个评价方向当成360个独立父本。

## 共同前向与反向

公式、占用和分支见[动态疲劳模型与伴随](动态疲劳模型与伴随.md)。所有方法共用最早开工、append-only、后阶段ECT/FAM的动态疲劳前向。无插空、右移、主动休息、疲劳硬阈值。记录负起点斜率，不暗示最早开工对可主动休息的问题最优。

完整伴随保留时间和疲劳状态的反向依赖；time_only 在**相同动态前向**上停止疲劳状态反向，Cmax方向对应普通时间关键路径，TEC/TWC方向是对应的时间通道控制。不能称后三者都是传统 Cmax 关键路径。

局部 defect 在旧前驱 C/v 上重算局部输出与费用，以 `sum(delta-direct-cost)+sum(old-costate*delta-local-state)` 预测。只包含首阶段显式编辑，后阶段模型、资源拓扑和伴随冻结。后续重排、活跃分支切换及大幅修改可能造成误差，必须由完整真实解码核验。

## 选择与真值隔离

分别诊断 Cmax、TEC、TWC、均衡三目标方向；尺度固定为父本目标向量，均衡权重各1/3。不是新增优化目标或 Pareto 算法。

先将全部预测分数与最低分平局集合写 `predictions.jsonl`，再完整解码候选。随机选择在相同16候选上均匀分布；最低预测分平局按相对/绝对1e-12容差，也均匀选择。报告两者的精确期望，禁止查看真值后挑平局中最好者。各法选择后统一可拒绝变差候选。

指标：Spearman（全同分时未定义并计数）、改善/非改善符号准确率、选中原始收益、拒绝变差后的接受收益、改善概率、相对于池内事后最好的 regret、平局规模。记录后阶段拓扑、活跃父节点、Cmax终点变化，区分导数正确与离散预测有效。无真实改善的候选也保留。

按疲劳场景和评价方向分别计算，配对差用实例→父本seed分层 bootstrap 2000次，保留六个实例簇结构。区间是小样本描述，不作总体优势或多重显著性宣称。

## 费用与调用口径

本机单线程 Python，`perf_counter_ns`，每项预热1次、测量5次并保留所有值。分别计时 minimal 解码、trace解码、候选生成、局部模块准备、一次目标方向的伴随、评分与均匀选择。trace与minimal使用同一前向物理函数，trace日志开销单列。

报告单次决策成本代理：指导法=父子各一次 trace 解码+生成候选+一次伴随+全部局部模块/评分/选择；随机=父子各一次minimal解码+生成候选+均匀选择。父本trace直接供伴随使用，不隐瞒为了取trace重复解码。分量中位数之和只是可解释代理，并非整套优化器等时间实验；测得收益/代理时间也不是长期搜索收敛速度。

所有完整调用按用途计数：父本90、事后真值1440、minimal计时540、trace计时540，共2610次；数学单元检查中的调用不属于机制实验，单独报告。局部模块不是完整FE，但计算时间全部保留。四方向评分不各自重复真值解码。
