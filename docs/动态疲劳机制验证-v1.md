# 动态疲劳机制验证 v1：实现成立，额外选择价值尚不稳定

共同动态疲劳解码器、完整伴随、时间通道控制和同池候选诊断已完成。数学导数与局部残差评分检查通过；本轮中，完整伴随通常优于随机选择，但相对时间通道的增量很小且随场景变化，计入耗时后未形成稳定优势。**当前证据不支持将它接入整套算法。**

本轮未修改 Java A0、PSO、QLS/QGS 或三目标契约。Python 原型为独立研究模块；疲劳来自合成参数，SUT/standby为公开重建，不是作者原成绩复现，也不是期刊级算法性能结论。

## 实现与数学证据

- `model.py / decoder.py`：共同动态前向、四向量语义、工机完整占用、稳定工序身份、真实拓扑日志、活跃分支与疲劳状态。minimal和trace走相同物理路径。
- `adjoint.py`：按真实执行拓扑倒序，传播完工时刻和疲劳状态，含能耗idle与工资的直接导数、多个父角色alias加和、明确的max平局规则。`include_fatigue=False` 是同一动态前向上的时间通道控制。
- `candidates.py / prediction.py`：同厂两工件合法编辑；只在旧前驱状态重算直接改变/重连的首阶段模块，再以旧伴随和直接费用差评分。评分不能读取候选完整真值。
- `case.py / timing.py / statistics.py`：先落盘预测和平局集合，再完整评价；均匀处理平局/随机，保留配对指标、组件计时与全部解码用途。
- 9项核心检查、4项候选隔离检查、1项事后补充的局部残差方向导数检查均通过，共14项；不因文字整理重跑实验。核心检查40个随机多厂多阶段小例×4个权重方向，完整解码和冻结拓扑各2400个base中央差分对照，最大scaled error分别 `1.1512e-9`、`1.4397e-9`。随机批次无分支改变，另有显式非光滑平局检查。
- 补充的残差方向检查在旧图逐工序注入 `theta*delta(C,v)` 及直接费用，对16候选×4方向验证评分等于theta=0处导数，容差1e-7。它支持评分公式实现，不能替代离散候选真值。
- 非关键工序手算：A并不在时间关键路径，但其疲劳影响B，`dC_B/db_A=.2195246544`；时间通道为0。这确认疲劳反向通道存在，不代表它在任意候选池中都具有足够的选择价值。

数学合同和分支公式见[动态疲劳模型与伴随](动态疲劳模型与伴随.md)。

## 固定实验与记录审查

严格按[运行前协议](动态疲劳机制验证协议-v1.md)：6个合格第四章实例×5个随机合法父本seed×3档合成疲劳，共90个父本/场景。每个池16个候选，共1440次完整候选核验。工厂分配不变，首阶段交换/插入顺序或资源，后阶段由共同ECT/FAM重新决定。三个选择器各用同一批候选，各方向归一化尺度固定为父本目标。

完整伴随、时间通道和随机分别比较Cmax、TEC、TWC及均衡三目标方向。Cmax的time_only对应普通关键路径；其他两个方向是相应的时间通道，不能都叫传统关键路径。三目标均衡只作标量诊断，不增加或替换Pareto目标。

原始产物：[本轮目录](../runs/fatigue-mechanism-v1-20261031-160753-449593/)、[机器汇总](../runs/fatigue-mechanism-v1-20261031-160753-449593/summary.json)、[完整分场景表](../runs/fatigue-mechanism-v1-20261031-160753-449593/report.md)、[记录审查](../runs/fatigue-mechanism-v1-20261031-160753-449593/audit.json)。

审查确认：90份输入、90份先行预测、1440份候选、1080份选择、90份计时完整；各疲劳场景的父本和候选一致；全部1080条选择指标从原始真值重算一致。物理时间轴和疲劳连续性核验全部通过。所有全解码共2610次：父本90、离线候选1440、minimal计时540、trace计时540；单元数学检查另计，未隐藏为在线FE。

## 预测和选择效果

下表是90个场景的描述性平均；`接受收益` 是相对父本归一化标量下降量，按各法相同的拒绝变差规则处理，平局和随机取均匀选择期望。三档参数的正式拆分保留在原始汇总中，四个方向不视为独立重复。

|方向|疲劳伴随Spearman|时间通道Spearman|疲劳伴随接受收益|时间通道接受收益|随机接受收益|
|---|---:|---:|---:|---:|---:|
|Cmax|0.068|0.058|2.472%|2.443%|0.647%|
|TEC|0.224|0.224|1.075%|1.072%|0.379%|
|TWC|0.221|0.179|0.273%|0.232%|0.101%|
|均衡三目标|0.138|0.124|1.109%|1.091%|0.323%|

Cmax完整伴随的符号准确率81.94%，但池中仅21.32%的候选真实改善，始终猜“非改善”已有78.68%的准确率；不能单凭81.94%宣称预测可靠。Cmax共有80/90个父本/场景的排序相关性可定义，另外10个全同分/同真值，不补成0。其他三个方向90/90可定义。

均衡方向完整伴随选中改善候选的概率70.0%，时间通道73.3%，随机50.3%；完整伴随平均接受收益略高，并不意味着改善概率也更高。360个场景/方向中，两种引导有241个相同的最低分候选集合。

按实例→父本seed分层的配对bootstrap（2000次、小样本描述）中，均衡方向“完整伴随减时间通道”的接受收益差为：

|疲劳场景|平均差，百分点|描述性95%区间，百分点|
|---|---:|---:|
|weak|+0.0100|[0.0000, +0.0501]|
|strong_slow_recovery|+0.0257|[-0.1720, +0.2548]|
|strong_fast_recovery|+0.0171|[-0.0719, +0.1889]|

这不支持稳定增量优势。其他方向也存在退化，例如强疲劳慢恢复下Cmax和强疲劳快恢复下TEC的平均差为负；不挑选TWC等较好结果作为总体结论。

## 时间是否值得

本机Python 3.11.7、numpy1.26.4、单线程组件测量。下列数值为各case预热后5次中位数再作描述平均；不能当作Java或完整搜索速度。

|组件/单次决策代理|平均毫秒|
|---|---:|
|minimal完整前向|0.950|
|trace完整前向|1.826|
|共同候选生成|3.619|
|全部候选局部defect准备|0.751|
|一次方向完整伴随|2.365|
|一次方向时间通道伴随|1.917|
|完整伴随指导决策代理|10.520|
|时间通道指导决策代理|10.072|
|随机决策代理|5.521|

决策代理包括父子各一次解码、候选生成、所需指导和选择，细目见协议。完整伴随指导自身平均3.250ms，约为3.70次minimal解码（逐case比值的均值）；trace/minimal比值均值1.92。不能声称日志和伴随仅额外消耗5%。完整伴随相对时间通道的总决策代理均值增加约4.45%；均衡方向的逐case接受收益/代理时间均值反而低约2.14%。三档场景各自的该收益率配对差区间均跨0。

相对随机，指导法能提高本轮单步选择质量，但额外成本明显；这只是同池决策代理，尚未证明整套算法在等时间或等FE下改善HV。共同候选生成在本原型中较贵；time_only也使用通用伴随框架，没有专门优化成轻量关键路径实现，这些成本都有优化空间，不能据此偏向完整伴随。

## 误差边界与后续判断

1440个编辑中1326个（92.1%）改变了后阶段资源/父节点拓扑，平均影响20.77个后阶段局部模块；首阶段直接改变模块最多9个。这与冻结旧拓扑的一阶评分误差风险一致，但本轮没有单独控制拓扑改变，不能认定它已被证明是唯一原因。导数检查正确与离散换序排序相关性较弱可以同时成立。

strong_fast_recovery父本累计出现101道 `dC/dS<0` 的工序，其他两档为0；它们均保留并标记，未剔除。共同最早开工解码在此仍可行，但没有主动休息决策，不能推广成对完整疲劳排程空间的最优解码。

本轮在此结束，不启动整套算法或扩展实验。下一项有价值的验证应区分固定拓扑小扰动与会触发重排的离散编辑，检查预测适用范围；在这点得到证据前，不宜叠加pbest、第二套Q-learning或进一步扩大算法复杂度。
