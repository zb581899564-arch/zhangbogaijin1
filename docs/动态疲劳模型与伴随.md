# 动态疲劳模型与伴随：独立机制原型

本模块位于 `research/fatigue_mechanism/`，用于小规模数学与机制验证，不接入或改动 Java A0、整套 MOPSO、预算入口或既有结果。它研究一个显式新物理模型；即使 beta=0，当前 append-only 解码也不等同于带插空/右移的规范 Java 解码，不能把不同解码器的目标差称为疲劳收益。

来源依据为本项目[模型合同](模型合同.md)、[实验比较协议](实验比较协议.md)，以及用户提供的 `D:/liulanqi下载/verify_fatigue_adjoint.py` 中的参考疲劳公式和反向递推。参考脚本仅只读，没有执行其 main，也没有复用其中 JSON 为本次已验证证据。该模型没有硬疲劳阈值，不提供主动休息、插空或右移。

## 状态、时间轴与三目标

每个工序有稳定身份 `i=k*N+j`；实际执行次序另存 `execution_order`。父节点顺序固定为 `(job, machine, worker)`，缺少前驱记为 -1、对应完工时刻为0。工序 id 大小不是拓扑次序：JS 可能先执行更大的 job-id，后续工序的父 id 也可能比自己大，反向必须按真实拓扑次序倒序。

工人和机器的本地 id 都在 `(factory, stage)` 中独立编号；全局唯一 `worker_uid(f,k,w)` 和 `machine_uid(f,k,m)` 仅用于参数和缓存索引。工人不能跨阶段共享。初始状态默认 `h0=0`；每工人也可显式指定 `[0,1]` 内初始疲劳。

记机器前驱完工为 `C_m`，工人前驱完工为 `C_w`、其疲劳输出为 `v_prev`；若无工人前驱则取该工人 h0。每道工序：

```text
S = max(C_job, C_m, C_w)
u = v_prev * exp(-mu * (S-C_w))
b = (ST[j,k] / MS[f,k,m] + SUT[j,k]) / WE[f,k,w]
d = b * (1 + beta*u)
C = S+d
v = 1-(1-u)*exp(-alpha*d)
energy = P*d + I*(S-C_m)  # 无机器前驱时该 gap 明确为0
labor = wage*d
```

设置时间不除以机器速度；机器和工人同时占用整个 `[S,C)`。所有 alpha/mu/beta 都非负、可按全局工人设置。模型仅返回 `[max(final-job-C), sum(energy), sum(labor)]` 三目标；首次机器开机前的等待不计 standby，末工序以后不计 standby，工人空闲不计费。

首阶段按 JS 过滤至各厂，FA/MA/WA 均为与 JS **位置对齐**的长度 N 向量。`Genome.by_job()` 返回工件属性映射；纯 JS 变换用 `Genome.from_job_attributes(new_js, attrs)`，使资源属性随工件移动。后阶段按上一阶段实际完工时间稳定 ECT/FIFO 排序，再各自选择最早空闲机器和工人，资源平局取最小本地 id。只 append，不回填空隙。每厂至少一个工件。

`dC/dS = 1-mu*beta*b*u` 可为负。每个 trace 显式存储 `negative_start_slope`，只报告这一非单调性；earliest-start 规则是固定解码策略，不能据此声称它对允许主动休息的问题最优。

## 接口与数据来源

`model.Instance` 显式接收 `processing[N,K]`、独立 `setup[N,K]`、`speeds/powers/standby[f][k][m]`、`efficiencies/wages[f][k][w]`，并强制非空的 `source/setup_source/standby_source`。输入数值复制为只读数组。别名 `jobs/n_jobs`、`stages/n_stages`、`factories/n_factories` 可用于脚本。

chapter4 文件自身缺失作者独立 SUT 和 standby，原型 loader 必须将重建来源公开；本模块不生成或猜测原作者数据。`data/chapter4` 的原始数值与 `docs/chapter4_instance_eligibility.json` 的36个严格资源合格清单不因此变成作者完整实例。合成检查明确标记 `SYNTHETIC`，不代替真实实例统计实验。

```python
result = decode(instance, genome, params, retain_trace=True)
rev = adjoint(result, instance, params, weights=(1,0,0), normscale=(1,1,1))
three = adjoint_objectives(result, instance, params)
```

`DecodeResult` 的 `operations` 按稳定 op-id 索引，`execution_order` 为真实拓扑。工序记录含 binding、parents、b/S/C/u/v/d、energy/labor、max 活跃分支、平局角色和负起点斜率标志。`makespan_ties` 记录并列的 final ops。`completion/fatigue` 数组还提供 `C/v` 别名。trace 携带完整来源三元组。

`retain_trace=False` 走**同一函数、同一前向物理路径**，不建立 OperationTrace 与执行顺序日志，只保留计算依赖必需的状态数组和目标，供 logging overhead 比较；无 trace 不能求伴随。不得为获取父代 trace 再全解码一次后隐藏其费用。

## 伴随与分支规则

局部输入列依次为 `x=(C_job,C_machine,C_worker,v_worker,b)`，输出 `y=(C,v)`。设 `ds` 是 max 的选定分支，`r=exp(-mu*(S-C_w))`、`e=exp(-alpha*d)`：

```text
du = -mu*u*ds + mu*u*dC_w + r*dv_prev
dd = b*beta*du + (1+beta*u)*db
dC = ds+dd
dv = e*du + alpha*(1-u)*e*dd
denergy = P*dd + I*(ds-dC_m)  # 仅已有机器前驱
dlabor = wage*dd
```

`adjoint` 使用 `weights / normscale`，尺度由外部传入，不随候选重算。先为选定 Cmax 末工序的 C 状态置权重，再按 `reversed(execution_order)` 做局部 Jacobian 转置传播，返回 `costates[N*K,2]` 和 `grad_base[N*K]`。本工序能耗/人工的直接导数同时加入 pullback。机器 idle 项直接依赖前驱完工，不能遗漏 `-I*dC_m`。同一个前驱可能承担多个父角色，必须逐角色累加，禁止用 dict 覆盖。

起点 max 平局按 job、machine、worker 优先；Cmax 平局按最小稳定 op-id。这是选定分支导数/子梯度，只在该分支继续活跃的一侧等于相应单侧导数；不同父状态恰好相等时一般没有唯一普通导数，不能用中央差分强行认定有错或宣称处处可微。检查器识别 max 分支变化与完整解码的拓扑/资源变化，单独计数并排除普通导数比较；同一前驱的多个角色 alias 视为同一状态分支。

`include_fatigue=False` 复用**同一次真实疲劳前向 trace**，只在反向冻结 u 和工时对上游状态的依赖，得到时间通道/关键路径控制。它保留本工序 `dd/db=1+beta*u`，但疲劳 costate 为0；不是 beta=0 的另一套前向问题。`Cmax` 方向时就只沿普通时间关键路径传播。

## 局部 defect 预测接口及适用边界

```python
local = local_transition(instance, params, op_id, new_machine, new_worker,
                         new_parents, cached_trace, factory_id=new_factory)
```

此函数只允许首阶段 op-id，用**旧 cached predecessor 的 C/v** 重算被改变的局部状态和局部费用；未传 factory_id 时沿用旧厂。它返回 `LocalTransition(C,v,energy,labor,b,d,u,S)` 对应属性。首阶段 JS 重连或 FA/MA/WA 替换由候选模块构造合法资源父节点；后阶段保持旧局部模型。`sum(delta-local-cost) + sum(lambda dot delta(C,v))` 是冻结局部模型下的一阶预测，跨拓扑、后阶段 ECT/FAM 切换和较大离散修改都可能产生误差，需候选完整重解码的真值评估。该真值不能提前输入选择器。`replay` 仅用于固定拓扑数值检查，不能冒充真实候选完整解码。

## 实际检查（2026-10-31）

执行：`python -m unittest research.fatigue_mechanism.checks.test_core -v`。9项检查通过，包括：

- 40个随机多厂、2/3阶段小例，四种权重（3个单目标及混合）；冻结拓扑 replay 与完整 decoder 各2400个 base 中央差分比较，最大 scaled error 分别 `1.439659358999279e-9` 和 `1.1511721714763112e-9`。该随机批次 branch-change 计数均0；另设真实不同父状态 max 平局，检查显式计数和选定分支单侧导数。
- 手算非关键 A→B：`b_A=4,b_B=8,t=10,alpha=mu=.1,beta=.5`，`C_B=18.723728779690337`，`dC_B/db_A=.2195246544376106`。冻结疲劳反向下 A 的 Cmax 梯度为0，说明新通道是通过恢复/累积状态传播。
- beta=0、alpha=0、mu=0、h0>0、归一化、多目标3-pass线性一致性；同一父节点角色 alias 加和与 idle 费用直接前驱项。
- 首阶段跨厂局部替换、禁止后阶段局部重绑、四向量随 job 移动、非自然 op-id 拓扑；工机完整工时互斥与疲劳连续、目标累加、最小前向与 trace 前向完全一致、负起点斜率标记。
- 批量 `local_transitions` 与逐次单点结果严格相同，整批仅验证/绑定一次参数数组，避免把重复参数校验当作伴随机制的必要开销。

这些证据支持本数学实现及局部导数，未证明候选预测有效、算法收敛、HV优势、主动休息最优性或原作者数值复现。正式算法结论仍需按实验比较协议冻结实例、重建数据、预算、种子和统计设计。
