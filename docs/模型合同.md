# 可执行问题模型合同（canonical-v1，2026-10-31）

本合同将三目标、调度时间轴和辅助工厂索引分开。`src/java/model/` 提供独立 Java 8 实现，无 jMetal 依赖；`src/java/modelchecks/` 提供手算与时间轴检查。它是有来源说明的规范重建基线，不是作者完整实验数据或算法的逐行复现。没有运行或宣称新算法实验。

## 证据与优先关系

- 原始 JMS：`../李明哲-毕业材料/smejms-Zhang2026可能第三.pdf`，Journal of Manufacturing Systems 85 (2026), pp.1–21。重点：p.4 式(10)、(15)–(18)，pp.5–6 表4/5及四向量，p.7 Algorithm 2。
- 原始 ESWA：`../李明哲-毕业材料/eswa2026-最新李明哲第四.pdf`，Expert Systems With Applications 306 (2026), 130934。重点：pp.5–6 式(8)、(12)–(23)，pp.7–9 表4/5、四向量及 Algorithm 2，p.15 §4.4.1，p.16 §5.1。
- 硕士论文：`../李明哲-毕业材料/3.毕业论文/104_2022930913_李明哲.pdf`，第四章§4.3（PDF p.66，印刷p.54）给出按阶段划分工人数的规则。当地提取文本 `docs/sources/*.txt` 及页图作为阅读辅助，数学式已结合原PDF页面核对。

两章是不同物理模型。第三章不能套用第四章按工件分配工人的 WA；第四章不能保留 `N*stages` 的全阶段 WA。期刊与硕士、代码不一致之处，下文逐项列明。

## 共同的输入、输出与标识

所有 Java 标识从0开始。论文图的1-based值读入前减1。JS 是工件排列；FA、MA、第四章WA均与 JS 的**位置**对应：`job=JS[p]`，`factory=FA[p]`，而不是用 job-id 去索引 FA。

所有工件在一个工厂顺序通过全部阶段，工厂之间不转移；阶段间运输时间为0；机器和工人在同一工序内不可中断；每厂至少分配一个工件。非空工序区间采用 `[start,end)`，首尾相接不重叠。

`Schedule.objectives()` 严格只有 `[Cmax, TEC, TWC]`，均最小化。`factoryMakespan()`、`factoryEnergy()`、`factoryCost()` 为独立数组，`criticalFactory(objective, maximum)` 返回对应工厂索引；相等时取最小工厂id。数组与工序集合均不给调用方可变内部引用。

`Operation` 保留 job/factory/stage/machine/worker、start、setupDuration、duration；`end=start+duration`，`processingStart=start+setupDuration`。所有资源冲突均可从这一时间轴检查。

## 第三章：固定工机绑定 DHHFSP-WME

JMS p.4/§4.2规定，每厂工人数等于该厂**全部阶段**机器总数，每名工人固定到该厂唯一的一台机器，厂内 WA 是工人全排列。WA 按 factory、stage、machine 依次展开；worker-id是该厂全工人池id，不在每阶段重置。

- `len(JS)=len(FA)=len(MA)=N`；MA 只编码首阶段机器。
- `len(WA)=ΣfΣk machines[f][k]`；每厂分段为其工人id的排列。
- 工序加工时间 `AT=ST/(MS*WE)`，没有设置时间。
- 每台使用机器的 `busy=Σ AT`，`span=lastFinish-firstStart`，`idle=span-busy`。
- `TEC=Σmachines (busy*processingPower + idle*standbyPower)`。
- `TWC=ΣusedMachines span*cost(boundWorker)`，包括该机器首工序开始至末工序完成之间的内部空闲；不支付首次开机前或末工序后的时间。

随附benchmark及小例的 worker效率/成本在机器间相同，当前 typed instance 对其使用 `WE[f][stage][worker]` 和 `cost[f][stage][worker]`。JMS符号更一般地包含 machine 下标；当前没有支持“同一工人在不同机器上不同效率/成本”的外部新数据，不能声称这个实现已覆盖该一般化实例族。

## 第四章：双资源 DR-DHHFSP-ST

ESWA p.7 明确四向量长度均为工件数，MA/WA仅编码**首阶段**机器与工人：`len(JS)=len(FA)=len(MA)=len(WA)=N`。worker-id是该厂该阶段的本地id。

ESWA式(13)：

```text
processingDuration = ST[j][k] / (MS[f][k][m] * WE[f][k][w])
setupDuration      = SUT[j][k] / WE[f][k][w]
AT                 = processingDuration + setupDuration
```

设置时间不除以机器速度，不由 ST 的10%派生。式(17)、(19)、(20)及 Algorithm 2 将机器和工人都占用至 `start+AT`，故实现中 worker 对完整 `[start,end)` 互斥。虽然p.7文字提到工人为机器设置，不能据此解释为“setup结束即释放工人”。工人可以先后操作同阶段不同机器，不能并发操作。

- `TEC=Σmachines (Σ AT*processingPower + internalIdle*standbyPower)`，设置时间也属于 AT 并按该机器加工功率计能耗，见式(22)。
- `TWC=Σoperations AT*workerCost`，见式(19)–(20)。第四章不支付内部等待时间；纯右移不会改变 TWC。
- `Cmax=max actualFinish`。只按完整可行时间轴计算，禁止把工厂id放入 objective 数组。

独立 SUT 数据是必要输入。45个随附benchmark没有 SUT 字段，当前未发现对应作者 SUT 文件或生成seed。ESWA p.16 只说明独立 `U[1,9]`，未足以恢复原数值。`SetupTimes.generatedSupplement(N,K,seed)` 使用 `java.util.Random` 按 job-major、stage-minor 顺序生成离散整数1至9，来源文本明确包含 `RECONSTRUCTED-NOT-AUTHOR-DATA`；这是用于工程与后续共同重建实例的独立补充数据，不能用于复现作者原表的数值结论。离散化同样是显式重建选择。

### 阶段工人池及严格实例范围

原文件只列每厂工人总数、效率和成本。硕士论文§4.3说 M<2 时 W=M、M>2时 W=M-1，遗漏 M=2。原代码对 M=2保留2，当前显式沿用这一分支。每厂 worker数据按stage连续切片，W总和必须等于文件给定总数，否则报错；不跨阶段共享工人。

ESWA 式(8)要求每厂至少一个阶段 W<M。当前45个第四章随附实例中，以下9个至少一个厂不满足此条件：

```text
50_2_3_1
100_2_4_1 100_2_5_1
150_2_3_1 150_2_4_1 150_2_5_1
200_2_3_1 200_2_4_1 200_2_5_1
```

它们的机器/工人数仍可得到合法时间轴，适合带标识的工程诊断。`Instance.satisfiesDualResourceCondition()` 会返回false，`provenance()`含 `ESWA-Eq8-NOT-SATISFIED`。不通过改资源伪造约束成立；严格论文模型实验应拒绝这些实例或事先另立重建实例协议。当前其余36个满足这一必要条件，不表示其他作者数据已被补齐。

## 解码中的明确重建规则

阶段1按JS位置过滤至各厂，使用显式MA及对应worker。阶段k>1按上一阶段实际完工时间排序，平局保留上一阶段顺序（稳定FIFO）；机器按最早可用时间FAM选择，平局最小机器id。第三章使用绑定worker。

第四章后阶段worker选最早可用者，平局最小worker id。期刊文字对最初可用workers提到随机选择，未提供解码seed/逐次随机规则；本实现将此歧义固定为确定性规则，避免同一四向量重复评价产生噪声。因此不能声称完全复现作者原解码随机过程。若未来改为有seed的随机选择，应独立升级模型版本并与当前共同解码器分开比较。

第四章微调在所选机器/工人的已排程区间中查找不早于前阶段完工的**最早公共空隙**，使整个 AT 同时容纳于两资源的空闲区间。先前安排不移动；新工序可插入所选资源的前部空隙，符合Algorithm 2查两类空闲区间的结构。

右移采用论文所述“不改Cmax而缩短内部闲置”的保守、确定性实现：按开始时间倒序处理，不移动每台机器末工序；对其余工序，将结束时刻最多推迟到机器后继、工人后继（第四章）、本工件下一阶段开始的最小值。持续时间、机器/工人绑定及资源顺序不变。每台机器末完工不变、首开始不早，故span和idle不增加；第三章TWC不增加，第四章TWC不变；工件末完成及Cmax不变。论文未提供完整逐步右移规则，本实现为公开可检验的工程补全，不能当新算法贡献。

## 公式与材料中的不一致

1. 两篇论文的部分 `C[j,k,f]` 展开式只写前阶段完成加 AT，未包含机器/工人等待；直接据其求机器span会与 `F=S+AT` 冲突。当前采用实际F及完整时间轴。
2. 两篇论文机器idle式含 `min(S*v)`，若把未分配该机器的工件也纳入，乘0会错误把最小值变0。实现的min/max严格限于分配该机器的工序；未使用机器能耗及成本为0。这与“机器首开至末完之间内部闲置”的文字/右移目的相符，属于明确的一致性解释。
3. JMS Fig.2左侧 MA 为 `[1,2,1,2,1]`，但第4个位置job4分配到factory2，表5其首阶段仅1台机，因而原图编码自身不可行。右侧解码图将该位置改为1。检查保留原始非法MA应被拒绝的断言；手算使用右侧可行解释 `[1,2,1,1,1]`，不静默修复输入。
4. `data/chapter3/150_2_3_1.txt` 在第一套worker块后还有一套不同效率/成本。loader依原DHFSP的读取行为选第一块，并验证后续worker块结构和计数，provenance记录忽略的块数，不改写输入。
5. 两章45个benchmark以及论文小例表均未提供 standbyPower。loader要求显式 `double standbyPower`；检查使用1，沿用旧代码单位待机项，但将其标为**重建假设**。不能视作作者独立提供参数，不能用该值宣称原实验数值恢复。
6. 第四章原源码以 `(ST+0.1ST)/(MS*WE)` 计算 AT、编码全阶段WA、部分路径把worker等待也计费，与ESWA期刊模型不同。本规范不保留这些物理语义，也不将修复称为算法创新。

## Java接入

```java
Instance c3 = InstanceLoader.loadChapter3(instancePath, explicitStandbyPower);
SetupTimes sut = SetupTimes.fromFile(sutPath, jobs, stages);
Instance c4 = InstanceLoader.loadChapter4(instancePath, sut, explicitStandbyPower);
Schedule result = Decoder.decode(instance, js, fa, ma, wa);
Validator.validate(instance, result); // 诊断/检查入口使用，不必在每次正式评价重复运行
double[] objectives = result.objectives(); // 长度3
double[] factoryCosts = result.factoryCost();
```

`loadChapter4(...,null,...)` 立即拒绝，不回退到10%。SUT文本为首行 `# source=<来源>`，其后N行、每行K个数，以逗号或空格分隔。来源为空拒绝。`SetupTimes.write` 仅新建文件，拒绝覆盖既有数据。没有缓存评价，Decoder调用本身不生成随机数、不改变输入；一次完整decode可由上层严格计作一次FE。预算、候选修复和失败FE归上层计数，不由模型层隐式吞掉。

Instance/Operation/Schedule/SetupTimes 均可Java序列化，支持不可变归档快照。`ModelKind` 明确区分两章，禁止凭WA长度猜模型。

## 已执行的必要检查

独立JDK 17下以 `--release 8` 编译，未新增依赖。完整命令（PowerShell）：

```powershell
$dest = Join-Path $env:TEMP 'limingzhe-model-checks'
New-Item -ItemType Directory -Path $dest -Force | Out-Null
$sources = Get-ChildItem src/java/model,src/java/modelchecks -Filter *.java | ForEach-Object FullName
javac -encoding UTF-8 --release 8 -d $dest $sources
java -cp $dest org.uma.jmetal.util.research.modelchecks.ModelChecks data/chapter3 data/chapter4
```

实际结果为 `MODEL_CHECKS_PASS`：90个实例，各3套有seed的合法编码，共270套；分别验证原排程和右移后每个工件全部阶段、工机互斥、持续时间、工件不跨厂、三目标有限、右移目标不增/Cmax不变，以及重复评价一致。额外检查：缺失SUT、非法图中MA被拒绝，Instance序列化往返。
