# 物理等价交错与教师对齐诊断（2026-11-05）

## 结论

确认：保持每厂有序 `(job,machine,worker)` 链，仅改变厂间 JS 交错，完整解码的时间轴和三目标精确不变；当前 QGS 和经典生成核的子代却通常改变。**这不是实现错误的证明，也没有证明去除这种依赖会更好。** 事前指定的接收方贪心对齐反而降低条件新增 HV，且增加耗时，停止该规则，不试反向排序、标准工厂顺序或仅保留正向角色。

[冻结协议、输入、类身份、原始子代与分析](../runs/neutral-view-probe-20261105-044126-106938/)。默认主线、四职责、QGS、固定 FA、原共享均未改。

## 设计与计费

复用此前已验收的两例、两个开发来源 seed10060007/10060031 的真实 QGS 输入。每个来源在四职责首代 step≥24 的首次 action2 批次等距取八个自由父代，合计每例64个场景；来源不是独立确认材料。没有新来源重放 FE，不按本轮收益筛选场景。

三种教师视图分别为原始 RAW、按剩余链长加权抽取的均匀随机交错 RANDOM，以及每步取接收方 JS 中位置最早的可用教师链头 ALIGNED。后者只是相对未扰动父代的贪心线性扩展，未证明最短交换距离。机器、工人及工厂元组始终随工件移动；教师自身的逐厂链不变。

每场景16份配对构造 seed；实际加载、未修改的 `KernelVariants.JOB_ALIGNED` 与 `CLASSIC_GLOBAL` 都使用三种视图。相同起始 seed 不保证修复之后仍逐次消耗相同随机数。每种方法同样评价16个子代，不事后挑每场景最好的方法。

- 正式探针12,672成功FE：384输入重放、12,288子代；工程另18成功FE；零失败。
- 正式探针16,640次中性视图完整解码 QA，12,288次子代完整时间轴 QA，全部精确一致。
- 原始核4,096次重复构造逐编码一致，父本与教师不变；等价自教师归一化恢复接收方编码。
- 全部新评价通过 `RunContext`。内部及共同修复沿用原核，最终共同修复编辑分别6,003/22,461，主要口径包括经典核合法化，不把非零修复计为评价失败。
- 方法成本包含视图准备、生成和付费评价，离线 QA、输入路径统计及输出单列。QA穿插可能影响微计时，成本门槛只描述本次探针；`contextSecondsIncludingQA` 不能用作在线时间，质量失败也不依赖成本判定。

## 结果

指标是相对该批次已付费档案加三份已知输入的**单子代条件新增 HV 均值**，不是完整算法 HV 或闭环增益。

两例覆盖达标，质量和必要成本关均失败。RANDOM 在两例方向不同，也没有资格升级为新算法。ALIGNED 虽在 CENTER 等角色有局部正信号，但工期角色损失52.689%/68.070%；这是总体停止依据的一部分，不能再挑角色重试。

## 可以和不可以解释什么

同一实际教师可以诱发不同子代，说明表示层存在额外搜索自由度。当前结果不支持“这种自由度主要是浪费、贴近接收者就会更好”；减少某种输入差异也可能压缩有用探索。未记录的真实 post-mutation 引导路径不能由输入路径统计替代。

一般冗余表示和归一化交叉已有 [Yoon等原始研究](https://arxiv.org/abs/0907.3202)，本轮未声称此概念新颖。没有完成完整算法、真正 TIME_LIMIT、独立实例或疲劳特异收益验证，研究 goal 仍 active。

下一项只做既有池诊断的覆盖核对：旧完整供给诊断保留了每厂已付费 Pareto 包络，但只评分九个线性 cap/eta 构造，不能称为所有笛卡尔组合的上界。若继续，需要精确求这些现成记录在 `max(C_f),sum(E_f),sum(W_f)` 下的组合闭包，并保持“离线容量 oracle”与“在线共享选择器”严格分开；不能改旧门槛、扫描权重或因此自动恢复旧池选择假设。
