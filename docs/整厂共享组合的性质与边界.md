# 整厂共享组合的性质与实现边界

本说明对应第五步固定FA家族的最小实现。以下是当前共同解码策略下的性质，不是关于任意调度模型的新定理，也不单凭它主张论文新颖性。

## 1. 为什么整厂记录可精确组合

固定实例、每个工件的工厂归属、全部加工/设置/功率/计薪/疲劳参数、初始状态和共同解码规则。记工厂f的完整工件集合为J_f，其首阶段本地编码为Γ_f，即本厂全部工件的相对顺序以及相应机器、工人。

在当前追加式解码器中，不同工厂没有共享机器、工人、跨厂工序前置约束、全局工资预算或全局疲劳约束。因此，对Γ_f的解码只依赖该厂上下文。其他工厂工件在全局JS中的插入位置不改变本厂资源状态及本厂工件相对顺序。

首阶段日程由Γ_f唯一确定；后阶段按共同FIFO及确定性的资源/并列规则解码，也由本厂既有完成时间唯一确定。逐阶段归纳可知，完整工厂日程及其三个贡献(c_f,e_f,w_f)均保持不变。因此任取相容整厂记录并写回一个合法全局四向量后，有

\[
C_{max}=\max_f c_f,\qquad TEC=\sum_f e_f,\qquad TWC=\sum_f w_f.
\]

该结论要求记录包含本厂全部工件从初始状态开始的完整日程。局部片段、改变后的工件集合、不同h0或不同解码规则不能直接套用。只匹配FA向量长度、工件数量或实例文件名均不够。

当前实现按厂拼接首阶段本地顺序，逐一写回机器/工人并保留家族标签。每个实际组合仍经共同正式评价器评价，计1 FE；上述公式只用于随后的预测一致性检查。结果档案不能凭方案池预测值直接收录未评价编码。

## 2. 有限池内何时可以逐厂独立选最优

给定各厂当前保留池P_f、跨度上限T、非负权重eta，以及冻结正尺度s_E、s_W，令

\[
P_f(T)=\{r\in P_f:c_f(r)\leq T\},\qquad
g_f(r)=e_f(r)/s_E+\eta w_f(r)/s_W.
\]

若任一P_f(T)为空，该组T下无法从这些池组成可行解。若每个集合均非空，联合可行集就是笛卡尔积∏_f P_f(T)，且

\[
\min_{r_f\in P_f(T)}\sum_f g_f(r_f)
=\sum_f\min_{r\in P_f(T)}g_f(r).
\]

证明直接来自两点：任意组合的每厂代价不小于该厂最小值；分别取每厂最小值又能同时达到这些最小值之和。全局跨度约束等价于每厂c_f≤T，故没有额外耦合。

这是**当前保留有限池**的最优选择，不是完整原问题的全局最优，不保证覆盖非凸Pareto前沿，不保证支配当前父本。它也不是全局人工成本预算的等价转写；若另加sum(w_f)≤B，独立选择通常不再成立。

## 3. 支配过滤与容量截断分别保留什么

若同上下文同厂记录a在(c,e,w)上支配b，则对任意T、eta≥0，b可行时a也可行，且g_f(a)≤g_f(b)。所以支配过滤不会丢失上述有限集合问题的最优目标值。相同局部编码去重同样安全。

容量上限8的多样性截断会删除某些非支配记录，因此可能丢失截断前池的最优解。实现只保证在**截断后池**内逐厂精确选择；极值保留和最大最小距离只是冻结的容量管理规则，不能称无损压缩或全局最优保持。

## 4. 固定FA家族带来的算法变化

每个家族以初始一粒子的按工件FA为锚，5粒子共享该FA；分群时各给三个边界群1粒子、综合群2粒子。80个自由粒子仍可跨厂探索。首版不刷新家族；它可能因固定上下文限制探索，这是需要由实验判断的代价。

普通更新/邻域在家族粒子上经过FA恢复与机器/工人重绑定，其实际邻域分布发生了变化。因此只比较SHARE与BASELINE不能把收益归给组合。SYNC含相同家族约束、重绑定、配额，关闭池与组合；VALUE_SYNC对VALUE_SHARE承担相同控制作用。

联合生成器识别固定FA并在候选可完成性阶段限制工件工厂，构造时就与正式解码保持相容。不能先在错误FA下计算前缀、再在评价前悄悄恢复FA并仍用原轨迹作学习标签。

## 5. 证据应分别回答什么

- 组合重放与上下文拒绝测试：实现正确性。
- SHARE-SYNC、VALUE_SHARE-VALUE_SYNC：给定相同家族约束时，池与组合是否有实际增量。
- SHARE-BASELINE：整个固定家族共享方案的净收益。
- VALUE-BASELINE与VALUE_SHARE-SHARE：价值生成器在无共享和有共享条件下的作用。
- (VALUE_SHARE-SHARE)-(VALUE-BASELINE)：预先定义的交互效果；仍受开发实例、seed和共同预算范围限制。

不能仅由VALUE_SHARE优于BASELINE就断言两个组件都有效；也不能由VALUE单用不占优就否定其在共享条件下的作用。四子群本身不是本轮新引入的组件，本轮结果只针对其上的联合生成及固定上下文共享方案。
